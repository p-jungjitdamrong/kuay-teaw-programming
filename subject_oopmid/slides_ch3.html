ติวบทที่ 3 · นิยาม

วัตถุคืออะไร + วงจรชีวิต 3 ช่วง

นิยามตามสไลด์
"วัตถุ คือ สิ่งๆ หนึ่งที่มีตัวตน
 มีข้อมูลและพฤติกรรม"

ข้อมูล     = field / attribute
พฤติกรรม  = method

วงจรชีวิตของวัตถุ (เรียงได้):
① สร้างและตั้งค่าเริ่มต้น (new + constructor)
② ใช้งาน (เรียก method / เข้าถึงข้อมูล)
③ ทำลาย (garbage collector เก็บกวาด)
สร้างด้วย new (ตัวอย่างสไลด์)
new String("ABC")
new Date()
new Integer(1)

/* ประโยคสำคัญในสไลด์:
   "วัตถุทุกตัวต้องมีชนิด
    และชนิดมันก็คือ คลาส"

   String s = new String("ABC");
   // s "อ้างถึง" วัตถุ ← คำนี้สำคัญ
   Date deadline;
   // ยังไม่อ้างถึงวัตถุใด (null) */
ศัพท์ที่ต้องใช้ให้ตรง: ตัวแปร "อ้างถึง (reference)" วัตถุ — ตัวแปรไม่ใช่ตัววัตถุ! ความเข้าใจนี้คือกุญแจของ 4 รูปแบบในสไลด์ถัดไป ซึ่งเป็นข้อสอบทฤษฎีตัวเป้งของบทนี้
ติวบทที่ 3 · หัวใจของบท (1/2)

4 รูปแบบตัวแปร-วัตถุ — แบบ ① และ ②

① 1 ตัวแปร 1 วัตถุ (ปกติ)
String s = new String("abc");
s.length() == 3;
s.equals("abc");  // true
s ───▶ ["abc"]
② 2 ตัวแปร 1 วัตถุ (ตัวหลอก!)
String s1 = new String("abc");
String s2;
s2 = s1;      // ชี้วัตถุเดียวกัน!
s1 = null;   // s1 ปล่อยมือ

s2.equals("abc");  // ยัง true!
// วัตถุยังอยู่ เพราะ s2 ยังชี้
s1 ──╳ ┌▶ ["abc"] s2 ──────┘ ยังเข้าถึงได้ผ่าน s2
จุดสอบของแบบ ②: s2 = s1 ไม่ได้ copy วัตถุ — แค่เพิ่มตัวชี้ · แล้วต่อให้ s1 = null วัตถุก็ยังไม่หาย เพราะยังมี s2 ชี้อยู่ (โยงถึง GC สไลด์หน้า)
ติวบทที่ 3 · หัวใจของบท (2/2)

แบบ ③ และ ④ — == vs equals โผล่ตรงนี้

③ 2 ตัวแปร 2 วัตถุ (ข้อสอบชอบสุด)
String s1 = new String("abc");
String s2 = new String("abc");

s2.equals(s1) == true;  // เนื้อหาเท่า
(s1 == s2) == false;    // คนละวัตถุ!
s1 ───▶ ["abc"] ← สองกล่อง s2 ───▶ ["abc"] เนื้อเหมือนกัน
④ 1 ตัวแปร 2 วัตถุ (วัตถุกำพร้า)
String s1 = new String("abc");
s1 = new String("cba");

/* สไลด์เขียนว่า:
   "ไม่มีตัวแปรใดเข้าถึงข้อความ
    abc ได้อีก"
   → "abc" กลายเป็นขยะ
   รอ garbage collector เก็บ */
s1 ──╳ ["abc"] ← ขยะ ไม่มีใครชี้ └───▶ ["cba"]
สูตรตอบข้อ == vs equals: วาดกล่อง! ลูกศรชี้กล่องเดียวกัน → == true · กล่องคนละใบเนื้อเหมือนกัน → == false แต่ equals true — วาด 10 วินาที ไม่มีทางตอบผิด
ติวบทที่ 3 · Garbage Collector

Object Destruction — GC ทำงานยังไง

ตามสไลด์
การคืนหน่วยความจำมี 2 วิธี:
① manual   → C++ (โปรแกรมเมอร์ delete เอง)
② อัตโนมัติ → Java!

"JRE มี garbage collector
 ไว้สำหรับคืนพื้นที่หน่วยความจำ

 ทำงานโดยวิ่งหาวัตถุที่
 เข้าถึงไม่ได้แล้ว (unreachable)
 แล้วทำการกำจัด
 คืนพื้นที่ให้ระบบปฏิบัติการ"
เชื่อมกับ 4 รูปแบบ
/* วัตถุไหนถูกเก็บ?
   → ตัวที่ "ไม่มีตัวแปรใดชี้ถึง"

   แบบ ②: s1=null แต่ s2 ยังชี้
   → ยังไม่ถูกเก็บ ✗
   แบบ ④: "abc" ไม่มีใครชี้
   → ถูกเก็บ ✓

   คำถามยอดฮิต:
   "Java ต่างจาก C++ เรื่อง
    หน่วยความจำอย่างไร"
   → Java มี GC อัตโนมัติ
     C++ ต้อง delete เอง */
เงื่อนไขเดียวที่ GC ใช้: วัตถุ unreachable (ไม่มี reference ชี้ถึง) — ไม่ใช่ "วัตถุเก่า" ไม่ใช่ "วัตถุใหญ่" · ตอบเกินจากนี้คือผิด
ติวบทที่ 3 · Class

Class = พิมพ์เขียว · โรงงานผลิตวัตถุ

นิยาม + เขียนคลาสแรก
/* สไลด์: "คลาสคือรูปแบบหรือ
   พิมพ์เขียว (blueprint) ของวัตถุ
   จัดกลุ่มวัตถุที่มีคุณสมบัติร่วมกัน
   โรงงานผลิตวัตถุตามพิมพ์เขียว" */

public class Book {
    String name;      // field
    double price;

    public Book(String n, double p) {
        name = n;     // constructor
        price = p;
    }
    public void show() {   // method
        System.out.println(name);
    }
}
กฎ constructor (ทวนจาก lab 3)
① ชื่อ = ชื่อคลาสเป๊ะๆ
② ไม่มี return type (void ก็ห้ามใส่)
③ ถูกเรียกอัตโนมัติตอน new
④ ไม่เขียนเลย → Java แถม
   default constructor ว่างๆ ให้
⑤ เขียนเองแล้ว → ตัวแถมหายทันที!
   new Book() จะ error ถ้าไม่มี
   constructor ว่างเขียนไว้
⑥ overload ได้ (หลายตัว
   ต่าง parameter)

/* เฉลย lab 3 เต็ม (Book, Box,
   Vector) → วิชา OOP Lab 2–7 */
ข้อกฎ ⑤ คือกับดักที่คนพลาดมากสุดในข้อเขียนโค้ด — ถ้าโจทย์ให้เขียน constructor รับค่า อย่าลืมว่า new Book() แบบว่างจะพังทันที เว้นแต่เขียนเพิ่มอีกตัว
ติวบทที่ 3 · โยง lab

ส่ง object เข้า method = ส่ง "รีโมท" ตัวเดียวกัน

โจทย์ resizeBox จาก lab 3
static void resizeBox(Box b, int fold) {
    b.width  *= fold;
    b.height *= fold;
    b.depth  *= fold;
}

Box b2 = new Box(3,4,5);  // vol 60
resizeBox(b2, 2);
b2.getVolume();          // 480!
ทำไมของจริงเปลี่ยน
main: b2 ──┐ ├──▶ [Box 3×4×5] method: b ──┘ ตัวเดียวกัน!
/* Java ส่ง "ค่าของ reference"
   b กับ b2 ชี้ Box ก้อนเดียวกัน
   แก้ผ่าน b = แก้ของจริง

   และ ×2 ทุกด้าน → ปริมาตร
   ×2³ = ×8 (60→480) ไม่ใช่ ×2!
   ← จุดสอบเลขที่คนพลาดประจำ */
เชื่อม 4 รูปแบบ: การส่ง object เข้า method คือ "2 ตัวแปร 1 วัตถุ" (แบบ ②) ชั่วคราวนั่นเอง — ทฤษฎีบทนี้อธิบายพฤติกรรมโค้ดใน lab ได้หมด

เช็คตัวเอง!
โค้ดนี้ มีการสร้างวัตถุกี่ตัว? และสุดท้ายเหลือวัตถุที่เข้าถึงได้กี่ตัว?

String a = new String("x");
String b = new String("y");
String c = a;
a = new String("z");
b = null;

ใบ้: new ทั้งหมด 3 ครั้ง = 3 วัตถุ ("x","y","z")
ไล่ดูทีละตัว: "x" มีใครชี้? (c!) · "y" มีใครชี้? · "z" มีใครชี้?
วัตถุที่ไม่มีใครชี้ = อาหารของ GC
ติวบทที่ 3 · ลองข้อสอบ

ผลของโค้ดนี้คือ?

String s1 = new String("abc");
String s2 = new String("abc");
System.out.println(s1 == s2);
System.out.println(s1.equals(s2));
s1 ───▶ ["abc"]     ← กล่องคนละใบ (new 2 ครั้ง)
s2 ───▶ ["abc"]
== ถามว่า "ลูกศรชี้กล่องเดียวกันไหม" → false
equals ถามว่า "ในกล่องเขียนเหมือนกันไหม" → true
