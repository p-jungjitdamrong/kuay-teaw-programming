Encapsulation — ตอบข้อบรรยายตามสไลด์

คำนิยามจากสไลด์ (จำโครงนี้)
"Encapsulation แปลตามตัวว่า
 การห่อหุ้ม

 • ห่อหุ้มข้อมูลของวัตถุไว้ภายใน
   โดยมี method เป็นเปลือกนอก
 • ห่อหุ้ม method ที่ไม่ต้องการ
   เปิดเผยไว้ภายใน

 วัตถุมี 'ด่านหน้า' รับข่าวสาร
 จากโลกภายนอก = ประกาศเป็น public
 ซ่อนคุณสมบัติภายใน = ประกาศ private"

← "หลักการเชิงวัตถุข้อที่ 1"
แปลงเป็นภาพ + เหตุผล
/*      ┌─ public method ─┐
        │  (เปลือก/ด่านหน้า) │
        │  ┌─ private ────┐ │
        │  │ field ข้อมูล  │ │
        │  └──────────────┘ │
        └──────────────────┘

   ทำไมต้องห่อ?
   ① กันคนนอกยัดค่าพัง
      (d.day = 99 ← กันได้)
   ② เปลี่ยนข้างในได้โดย
      คนใช้ไม่กระทบ
   ③ ตรวจสอบ (validate)
      ก่อนรับค่าเสมอ */
สไลด์เตือนตรงๆ ว่า: "ไม่ควรใช้ public attribute อย่างยิ่ง" — ถ้าข้อสอบถามว่า field ควรเป็นอะไร ตอบ private + เปิด getter/setter เสมอ
ติวบทที่ 4 · ตารางบังคับจำ

ตาราง Access Modifiers — กาให้ถูกทุกช่อง

เข้าถึงจาก →คลาสตัวเองpackage เดียวกันคลาสลูก (ต่าง pkg)ทุกที่
public✓✓✓✓
protected✓✓✓✗
(ไม่ระบุ = default)✓✓✗✗
private✓✗✗✗
 
/* วิธีจำ: เรียงจากกว้าง → แคบ
   public > protected > default > private
   แต่ละขั้น "หด" ลงทีละวง

   default (ไม่เขียนอะไรเลย):
   "เรียกได้จาก class ใน
    package (folder) เดียวกัน"
   ← นิยามในสไลด์ตรงๆ */
/* จุดหลอก 2 จุด:
   ① default ≠ public!
     ไม่เขียน modifier ไม่ใช่
     เปิดหมด — จำกัดแค่ package
   ② protected กว้างกว่า default
     ตรง "คลาสลูกต่าง package"
     ← ช่องเดียวที่สองแถวต่างกัน
     ข้อสอบชอบเจาะช่องนี้! */
ก่อนสอบ: วาดตารางนี้จากความจำ 1 รอบ — 4 แถว × 4 ช่อง ใช้เวลา 1 นาที ได้คะแนนทุกข้อที่ถาม modifiers
ติวบทที่ 4 · Class Modifiers

Class Modifiers — abstract / final / public / ไม่มี

ตามตารางในสไลด์
abstract  มี abstract method
          อย่างน้อย 1 method
          (ไม่มี body มีแต่ header)
          → new ตรงๆ ไม่ได้

final     "มี subclass ไม่ได้"
          → ห้าม extends ต่อ!

public    instantiate ได้ +
          เรียกใช้ได้จากทุก class

ไม่มี     เรียกใช้ได้จาก class
          ใน package เดียวกัน

private   เป็น inner class เท่านั้น
          (class ซ้อนใน class)
คู่ตรงข้ามที่ชอบถาม
/* abstract vs final = ตรงข้ามกัน!

   abstract: "ต้องมีลูกมาสานต่อ"
             (new เองไม่ได้)
   final:    "ห้ามมีลูก"
             (extends ไม่ได้)

   → class เดียวเป็นทั้ง
     abstract และ final ไม่ได้!
     (ขัดแย้งกันเอง)
   ← ข้อ "ข้อใดผิด" ชอบเอามาออก

   ตัวอย่างจริง: String เป็น
   final class — สืบทอดไม่ได้ */
ถามแนวนี้: "class ที่ไม่ต้องการให้ใครสืบทอด ใช้ modifier ใด" → final · "class ที่มี method ไม่มี body ต้องประกาศเป็น" → abstract
ติวบทที่ 4 · Syntax เต็มรูป

โครงประกาศ class เต็มรูป — สไลด์ให้ template นี้

[<Class_modifier>] class <class-name>
        [extends <superclass-name>]
        [implements <interface_1>, <interface_2>, ...] {

    // field:  [<modifier>] <type> <field-name>;
    private String name;

    // method: [<modifier>] <return type> <method-name>([<parameters>]) { body }
    public String getName() {
        return name;
    }
}
/* ลำดับใน [ ] ต้องจำ:
   extends มาก่อน implements!

   class A extends B implements C, D ✓
   class A implements C extends B ❌

   extends ได้ "ชื่อเดียว"
   implements ได้ "หลายชื่อ" คั่น , */
/* ข้อเติม syntax ชอบเว้น:
   - ช่อง modifier
   - ช่อง return type
   - ลำดับ extends/implements

   เขียน template นี้ได้
   = ทำข้อเติมได้ทั้งชุด */
กฎเหล็ก: extends ก่อน implements เสมอ · extends แม่เดียว · implements หลาย interface ได้ — สามข้อนี้พอสำหรับทุกข้อ syntax ประกาศคลาส
ติวบทที่ 4 · ลงมือ

getter / setter + validation — ท่าเขียนมาตรฐาน

โครง (จาก lab 4: Date)
public class Date {
    private int day;

    public int getDay() {
        return day;
    }
    public void setDay(int day) {
        if (day >= 1 && day <= 31)
            this.day = day;
        // นอกช่วง → เก็บค่าเดิม
    }
}
จุดให้คะแนน 3 จุด
① field เป็น private เสมอ
② setter มี validation
   (ค่าเพี้ยน → ไม่รับ)
③ this.day แยก field จาก
   parameter ชื่อซ้ำ

/* getter แปลงค่าได้ด้วย:
   getYear() { return year + 543; }
   ← เก็บ ค.ศ. คืน พ.ศ. (โจทย์ lab!)

   เฉลย lab 4 เต็มทุกข้อ
   (Date, BankAccount, ร้านโชห่วย)
   → วิชา OOP Lab 2–7 บท Lab 4 */
read-only property: balance ของ BankAccount มี getter แต่ไม่มี setter — เงินต้องเปลี่ยนผ่าน deposit/withdraw เท่านั้น · แนวคิดนี้เป็นข้อบรรยายได้ ("ทำไมไม่ควรมี setBalance")
💭
เช็คตัวเอง!
class A อยู่ package p1 · class B extends A อยู่ package p2
field ใน A ประกาศแบบไหน ให้ B ใช้ได้ แต่ class อื่นนอก p1 ใช้ไม่ได้?

ไล่ตาราง: public → ทุกที่ใช้ได้ (กว้างไป)
default → B ต่าง package ใช้ไม่ได้ (แคบไป)
private → แม้แต่ B ก็ใช้ไม่ได้
เหลือตัวเดียว... protected!

นี่คือช่อง "คลาสลูกต่าง package" ที่เป็นจุดแตกต่าง
ระหว่าง protected กับ default — จุดที่ข้อสอบชอบเจาะ
ติวบทที่ 4 · ลองข้อสอบ

field ที่ไม่เขียน modifier เลย ใครเข้าถึงได้บ้าง?

public > protected > default > private   (กว้าง → แคบ)
default ≠ public!  ไม่เขียน modifier = จำกัดอยู่ใน package (folder) เดียวกัน
