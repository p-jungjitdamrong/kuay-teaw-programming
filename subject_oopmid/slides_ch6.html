ติวบทที่ 6 · นิยาม

Inheritance + Is-A Rule — "มีทิศทาง"

นิยามตามสไลด์
"การสืบทอดคุณสมบัติ คือ
 หลักการเชิงวัตถุประการที่ 2

 ความสัมพันธ์ของคลาส 2 คลาส
 ที่คลาสหนึ่งถ่ายทอดคุณสมบัติ
 ให้อีกคลาส
 เหมือนแม่ถ่ายทอดพันธุกรรมให้ลูก

 คลาสแม่ = super class
 คลาสลูก = sub class"

/* วิธีทดสอบ: ถามคำถาม "is-a" */
Is-A มีทิศทาง! (สไลด์เน้น)
✓ sub is a super:
  Student is a Person       ✓
  Monkey  is an Animal      ✓

✗ super is NOT a sub:
  Person is not a Student   ✗
  Animal is not a Monkey    ✗

/* ทิศเดียวเท่านั้น!
   ลูกเป็นแม่ได้ แม่เป็นลูกไม่ได้

   ← ข้อ True/False สายนี้
   หลอกด้วยการกลับทิศประจำ */
ใช้ is-a ตัดสินใจ design: "Student เป็น Person ไหม" ใช่ → extends ได้ · "BankAccount เป็น Date ไหม" ไม่ → ใช้ has-a (field) แทน — ข้อสอบให้ scenario แล้วถามว่าควรใช้ inheritance หรือไม่
ติวบทที่ 6 · ตัวอย่างสไลด์

Person / Student — โค้ดตามสไลด์อาจารย์

public class Person {
    protected String name;                  // protected → ลูกเข้าถึงได้ (บท 4!)
    protected String surname;
    protected int age;

    public Person(String first, String last, int a) {
        name = first; surname = last; age = a;
    }
    public void setAge(int age) { this.age = age; }
    public void printInfo() {
        System.out.println(name + " " + surname + " " + age);
    }
}

public class Student extends Person {
    private int year;
    protected String tutor;

    public Student(String f, String l, int a, int y, String t) {
        super(f, l, a);      // ① เรียก constructor แม่ — บรรทัดแรกเสมอ!
        year = y;            // ② แล้วค่อยของตัวเอง
        tutor = t;
    }
}
3 กฎ super: ① super(...) ต้องบรรทัดแรกของ constructor ② ไม่เขียน → Java แอบเรียก super() ว่าง (ถ้าแม่ไม่มีตัวว่าง = compile error!) ③ super.method() เรียกใช้ของแม่ตอน Override
ติวบทที่ 6 · ข้อบรรยายชัวร์

ข้อดี-ข้อเสียของ Inheritance (สไลด์มีสองหน้าเต็มๆ)

ข้อดี (Advantages)
① ลดโค้ดซ้ำ
   "แชร์รหัสร่วมระหว่างหลายคลาสย่อย"
   โค้ดซ้ำใน 2 คลาส → refactor
   ย้ายขึ้นไปไว้ที่ superclass

② จัดกลุ่มวัตถุ/คลาสได้เป็นระบบ

③ ยืดหยุ่นต่อการเปลี่ยนแปลง
   คลาสที่สืบทอดจาก superclass
   เดียวกัน "ใช้สลับกันได้"
   (ถ้าชนิดคืนเป็น superclass)
   ← ปูทางไป Polymorphism
ข้อเสีย (Disadvantage)
"ความสัมพันธ์แบบสืบทอดเป็น
 ความสัมพันธ์ที่ แน่นแฟ้น
 (tightly coupled)
 ระหว่างแม่กับลูก

 ถ้าเปลี่ยนโค้ดของคลาสแม่
 จะมีผลต่อคลาสลูก ทั้งหมด
 ที่สืบทอดมา"

/* ตอบข้อ "จงบอกข้อเสียของ
   inheritance" ด้วยประโยคนี้
   — มาจากสไลด์คำต่อคำ */
ข้อบรรยายสูตรสำเร็จ: ถ้าโจทย์ให้ "อธิบาย inheritance พร้อมข้อดีข้อเสีย" → นิยาม (แม่ถ่ายทอดให้ลูก, is-a) + ข้อดี 3 (ลดโค้ดซ้ำ/จัดกลุ่ม/ยืดหยุ่น) + ข้อเสีย 1 (แน่นแฟ้น แก้แม่กระทบลูกทั้งหมด) — ครบ = คะแนนเต็ม
ติวบทที่ 6 · Override + ภาพรวม

Override + ตำแหน่งของบทนี้ใน 4 เสา OOP

Override — ลูกเขียนทับ method แม่
public class Student extends Person {
    // เขียนทับ printInfo ของแม่
    public void printInfo() {
        super.printInfo();  // reuse แม่
        System.out.println("Year: " + year);
    }
}

/* กติกา Override:
   ชื่อ + parameter + return type
   ต้องเหมือนแม่เป๊ะ
   (ต่าง parameter = Overload
    ไม่ใช่ Override! คนละเรื่อง) */
แผนที่ 4 เสา (สอบ midterm ถึงไหน)
① Encapsulation  ← บท 4 ✓
   (ห่อหุ้ม private + getter/setter)
② Inheritance    ← บท 6 ✓ (บทนี้)
   (สืบทอด extends + is-a)
③ Polymorphism   ← หลัง midterm
   (หลายร่าง — lab 7 เป็นต้นไป)
④ Abstraction    ← โผล่บางส่วน
   (abstract class ในตาราง modifier)

/* ถาม "หลักการเชิงวัตถุข้อ 1 คือ"
   → Encapsulation
   "ข้อ 2 คือ" → Inheritance
   ← เลขข้อมาจากสไลด์ตรงๆ */
คู่ที่ห้ามสับสน: Override = ลูกทับ method แม่ (หัวเหมือนเป๊ะ) · Overload = method ชื่อเดียวกันหลายตัวใน "คลาสเดียวกัน" ต่าง parameter — ข้อสอบถามแยกสองคำนี้บ่อยมาก
