กติกาของวิชานี้: ทุกโจทย์จะเดินครบ 5 ขั้นให้ดู — อย่าเพิ่งดูเฉลยโค้ด ให้ลองทำถึงขั้น ③ (ผังงาน) ด้วยตัวเองก่อนเสมอ นั่นคือจุดที่ทักษะเกิดจริง
STEP 1 · อ่านโจทย์

อ่านโจทย์ให้แตก — จับ 3 อย่างนี้ก่อน

โจทย์ตัวอย่าง
โจทย์: รับคะแนนนักเรียน n คน แล้วแสดงคะแนนเฉลี่ย และบอกว่ามีกี่คนที่ได้คะแนนสูงกว่าค่าเฉลี่ย
แยก 3 อย่าง
INPUTn (จำนวนคน) และคะแนน n ตัว
OUTPUT① ค่าเฉลี่ย ② จำนวนคนที่เกินค่าเฉลี่ย
เงื่อนไข"สูงกว่า" = มากกว่าเท่านั้น (ไม่รวมเท่ากับ)
สิ่งที่ได้จากการแยก
# รู้ทันทีว่า:
# • ต้องรับค่าหลายตัว → ใช้ลูป
# • ต้อง "เก็บไว้ใช้ทีหลัง" → ต้องมี array/list
#   (เพราะต้องวนรอบสองเพื่อเทียบกับค่าเฉลี่ย!)
# • ต้องมีตัวสะสม 2 ตัว: total กับ count
คำถามที่ต้องถามตัวเองทุกครั้ง
□ ต้องรับข้อมูลกี่ตัว? รู้จำนวนล่วงหน้าไหม
  → รู้ = for  ·  ไม่รู้ = while

□ ต้องใช้ข้อมูลซ้ำอีกรอบไหม
  → ใช้ซ้ำ = ต้องเก็บใน array/list
  → ใช้ครั้งเดียว = ประมวลผลทันทีได้

□ output มีกี่อย่าง
  → แต่ละอย่างต้องมีตัวแปรรองรับ

□ มีคำที่กำกวมไหม
  → "สูงกว่า" vs "ไม่ต่ำกว่า" ต่างกัน!
คำที่ต้องอ่านให้ละเอียด: "มากกว่า" (>) vs "ไม่น้อยกว่า" (≥) · "ระหว่าง 1-10" รวม 1 กับ 10 ไหม · "หารลงตัว" = % == 0 — คำเดียวเปลี่ยนคำตอบทั้งข้อ
STEP 2 · แตกปัญหา

ขั้นที่สำคัญที่สุด — ซอยจนเล็กพอจะเขียนได้

จากโจทย์เดิม — ซอยเป็นขั้น
โจทย์ใหญ่: "หาค่าเฉลี่ยและนับคนที่เกิน"

ซอยเป็น:
  ① รับ n
  ② รับคะแนน n ตัว เก็บใน list
  ③ หาผลรวม
  ④ คำนวณเฉลี่ย = ผลรวม / n
  ⑤ วนอีกรอบ นับคนที่ > เฉลี่ย
  ⑥ แสดงผล

← แต่ละขั้นตอนนี้ "เขียนโค้ดได้เลย"
  โดยไม่ต้องคิดอะไรเพิ่ม
  = ซอยละเอียดพอแล้ว
เทคนิคซอย 3 แบบ
① ซอยตามลำดับเวลา
   "ก่อนอื่นต้อง... แล้วค่อย... สุดท้าย..."

② ซอยตาม output
   output มี 3 อย่าง → แยกคิดทีละอย่าง
   ว่าแต่ละอย่างต้องใช้อะไรบ้าง

③ ซอยจากตัวอย่าง (ทรงพลังที่สุด)
   ลองทำด้วยมือกับตัวเลขจริง
   แล้วจดว่า "มือเราทำอะไรบ้าง"
   → นั่นคือขั้นตอนของโปรแกรม
เกณฑ์ว่าซอยพอหรือยัง
ถามตัวเอง:
"ขั้นนี้ เขียนเป็นโค้ดได้กี่บรรทัด?"

  1-5 บรรทัด → พอแล้ว ✓
  ยังตอบไม่ได้ → ซอยต่อ
เทคนิค "ทำด้วยมือก่อน" คือของจริง: เจอโจทย์ที่คิดไม่ออก ให้เอาตัวเลขตัวอย่างมาทำด้วยมือบนกระดาษ แล้วสังเกตว่าตัวเองทำอะไรซ้ำๆ — สิ่งที่ทำซ้ำคือลูป · สิ่งที่ต้องตัดสินใจคือ if
STEP 2 · หา pattern

แปลง "สิ่งที่ทำซ้ำ" ให้เป็นลูป

ตัวอย่าง: พิมพ์สามเหลี่ยม
แถว 1: * แถว 2: ** แถว 3: *** แถว 4: ****
ทำด้วยมือแล้วสังเกต:
  แถว 1 → พิมพ์ * 1 ตัว
  แถว 2 → พิมพ์ * 2 ตัว
  แถว 3 → พิมพ์ * 3 ตัว

pattern: แถว i → พิมพ์ * i ตัว
         └────┬────┘
       ลูปนอก = แถว
       ลูปใน  = จำนวนดาว (ตาม i)
ตารางหา pattern — ใช้ได้ทุกโจทย์
รอบที่ (i)ทำอะไรเป็นสูตรว่า
1ดาว 1 ตัวi
2ดาว 2 ตัวi
3ดาว 3 ตัวi
nดาว n ตัวi
 
# ได้สูตรแล้ว → เขียนลูปได้ทันที
for i in range(1, n+1):
    for j in range(i):      ← ใช้สูตรตรงนี้
        print("*", end='')
    print()
# pattern แบบอื่นที่เจอบ่อย
แถว i มี (n−i) ตัว   → ลดลง
แถว i มี (2i−1) ตัว  → 1,3,5,7 (เลขคี่)
แถว i เว้นวรรค (n−i) → ทำให้ชิดขวา
สูตรทองของโจทย์ลูป: ทำตารางว่า "รอบที่ i ทำอะไร" 3-4 รอบ แล้วหาว่ามันสัมพันธ์กับ i ยังไง — ได้สูตรเมื่อไหร่ เขียนลูปได้ทันที
STEP 3–4 · ผังงาน → โค้ด

แปลงกล่องเป็นบรรทัด — ตารางแปลงตรงตัว

ผังงานCPython
▱ รับข้อมูลscanf("%d",&x);x = int(input())
▭ คำนวณy = x * 2;y = x * 2
▽ แสดงผลprintf("%d", y);print(y)
◇ ตัดสินใจif (x > 0) { }if x > 0:
◇ + ย้อนกลับwhile (i < n) { }while i < n:
วนตามจำนวนfor(i=0;i<n;i++)for i in range(n):
ตรรกะเหมือนกัน ต่างแค่ไวยากรณ์
/* C — ต้องประกาศชนิด + { } + ; */
#include <stdio.h>
int main() {
    int i, sum = 0;
    for (i = 1; i <= 10; i++) {
        sum += i;
    }
    printf("%d\n", sum);
    return 0;
}
# Python — ไม่ต้องประกาศชนิด ใช้เยื้อง
sum = 0
for i in range(1, 11):
    sum += i
print(sum)
# ผังงานเดียวกัน → โค้ด 2 ภาษา
# ← นี่คือเหตุผลที่ต้องวาดผังงานก่อน
#   คิดครั้งเดียว ใช้ได้ทุกภาษา
ข้อดีของการวาดผังงานก่อน: แยก "การคิด" ออกจาก "การจำ syntax" — คิดจบแล้วค่อยกังวลว่า C ต้องมี ; หรือ Python ต้องเยื้อง · คนที่ตันมักพยายามทำสองอย่างพร้อมกัน
STEP 5 · ทดสอบ

เคสขอบ — จุดที่โปรแกรมมักพัง

เช็คลิสต์เคสที่ต้องลอง
เคสตัวอย่าง
ตัวอย่างโจทย์ต้องตรงเป๊ะทุกตัว
ค่าน้อยสุดn = 1, list มีตัวเดียว
ค่าว่างn = 0, list ว่าง, string ว่าง
ค่าติดลบ−5, −1
ศูนย์0 (โดยเฉพาะตัวหาร!)
ค่าเท่ากันหมด[5,5,5]
เรียงกลับด้าน[5,4,3,2,1]
บั๊กยอดฮิตที่เคสขอบจับได้
# ① หารด้วยศูนย์
avg = total / n        ← n = 0 → พัง!
if n > 0:
    avg = total / n

# ② list ว่าง แต่ไปหยิบ [0]
mx = a[0]              ← a = [] → IndexError
if len(a) > 0:
    mx = a[0]

# ③ ค่าเริ่มต้นของ max ผิด
mx = 0                 ← ถ้าข้อมูลติดลบหมด
                         จะได้ 0 ซึ่งผิด!
mx = a[0]              ← ถูกต้อง

# ④ off-by-one
for i in range(1, n)   ← ขาดตัวสุดท้าย
for i in range(1, n+1) ← ถูก
นิสัยที่ควรติด: เขียนเสร็จปุ๊บ ลองเคส n=0, n=1, ค่าติดลบ ทันที — สามเคสนี้จับบั๊กได้เกินครึ่งของบั๊กทั้งหมด และเป็นเคสที่ข้อสอบชอบซ่อนไว้
เครื่องมือเสริม · หาบั๊ก

ผลไม่ตรง — หาบั๊กด้วยตาราง trace

โค้ดที่ผลไม่ตรง
# ต้องการผลรวม 1..5 = 15
# แต่ได้ 10
total = 0
for i in range(1, 5):
    total += i
print(total)

2 เครื่องมือหาบั๊ก: ตาราง trace (ทำบนกระดาษ ใช้ในห้องสอบได้) · print ดักค่า (ตอนเขียนจริงบนเครื่อง) — ทั้งคู่ตอบคำถามเดียวกันคือ "ตัวแปรมีค่าอะไรในแต่ละรอบ"
ตัวอย่าง · เดินครบ 5 ขั้น

ลองเดินครบทั้ง 5 ขั้นกับโจทย์เดิม

โจทย์: รับคะแนน n คน แสดงค่าเฉลี่ย และนับว่ามีกี่คนได้สูงกว่าค่าเฉลี่ย
STEP 1 — อ่านโจทย์
  IN : n, คะแนน n ตัว
  OUT: ค่าเฉลี่ย, จำนวนคนที่ > เฉลี่ย
  เงื่อนไข: "สูงกว่า" = > (ไม่รวมเท่ากับ)

STEP 2 — แตกปัญหา
  ① รับ n
  ② วนรับคะแนน เก็บใน array/list
  ③ หา total
  ④ avg = total / n
  ⑤ วนอีกรอบ นับ x > avg
  ⑥ แสดงผล
  ← ต้องเก็บใน array เพราะใช้ 2 รอบ!

STEP 3 — ผังงาน
▱ รับ n ↓ ┌▶◇ i < n ──เท็จ─┐ │ ▱ รับ a[i] │ │ ▭ total+=a[i] │ └──▭ i++ │ ┌─────────┘ ▭ avg = total/n ▭ count = 0 ↓ ┌▶◇ i < n ──เท็จ─┐ │ ◇ a[i] > avg │ │ ▭ count++ │ └──▭ i++ │ ┌─────────┘ ▽ แสดง avg, count
STEP 4 — เขียนโค้ด (Python)
n = int(input())
a = []
for i in range(n):
    a.append(int(input()))

total = sum(a)
avg = total / n

count = 0
for x in a:
    if x > avg:
        count += 1

print(f"เฉลี่ย {avg:.2f}")
print(f"สูงกว่าเฉลี่ย {count} คน")
STEP 5 — ทดสอบ
  n=3, [10,20,30] → avg 20.00, count 1 ✓
  n=1, [50]       → avg 50.00, count 0 ✓
  n=3, [5,5,5]    → avg 5.00,  count 0 ✓
                    (เท่ากันไม่นับ ถูกตามโจทย์)
  n=0             → ⚠️ หารศูนย์!
                    → ต้องเช็ค if n > 0
สังเกตว่า STEP 5 จับบั๊กที่ STEP 1-4 มองไม่เห็น (n=0 หารศูนย์) — นี่คือเหตุผลที่ต้องทดสอบเคสขอบเสมอ ไม่ใช่แค่ตัวอย่างที่โจทย์ให้
