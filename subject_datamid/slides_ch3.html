ติวบทที่ 3 · Selection

Selection Sort — pseudocode อาจารย์ + วิธีอ่าน

จากสไลด์อาจารย์ (จำโครงนี้)
Selection-Sort(A, n)
1. for i = 0 to n-2 do
2.    min ← i
3.    for j = i+1 to n-1 do
4.       if A[j] < A[min] then
5.          min ← j
6.    swap(A[i], A[min])
แปลเป็นภาษาคน
รอบ i: มองช่วง A[i..n-1]
  ① เดาว่า A[i] คือตัวน้อยสุด (min=i)
  ② ไล่ดู j ถัดไปทั้งหมด
     เจอตัวน้อยกว่า → จำตำแหน่ง (min=j)
  ③ จบรอบ สลับ A[i] ↔ A[min]
     → ตัวน้อยสุดมาอยู่หน้า

ทำ n-1 รอบ (i = 0 ถึง n-2)
รอบละ 1 swap เท่านั้น
ที่ข้อสอบชอบถาม: จำนวนเปรียบเทียบรวม = (n−1)+(n−2)+...+1 = n(n−1)/2 → O(n²) — สูตร Gauss จากบท 2 กลับมาแล้ว! และ Selection ไม่มี Best case ที่ดีกว่า: Best = Worst = O(n²)

ติวบทที่ 3 · Bubble

Bubble Sort — เทียบคู่ติดกัน + นับ swap

หลักการ + โครงรอบ
รอบที่ 1: เทียบ (0,1)(1,2)...(n-2,n-1)
  ถ้าซ้าย > ขวา → สลับ
  จบรอบ: ตัวใหญ่สุดไปอยู่ท้าย ✓

รอบที่ 2: เทียบถึงแค่ n-2
  (ท้ายสุดเรียงแล้ว ไม่ต้องเทียบ)

...ทำจนครบ n-1 รอบ
   หรือรอบไหนไม่มี swap เลย = จบ

/* ใบ practice ให้ตาราง:
   รอบ 1 มี 5 แถว, รอบ 2 มี 4 แถว...
   → เขียน 1 แถวต่อ 1 การเทียบ! */
ตัวอย่าง: 5 3 8 1 (นับ swap)
รอบ 1:
(5,3) สลับ → 3 5 8 1   swap#1
(5,8) ไม่สลับ → 3 5 8 1
(8,1) สลับ → 3 5 1 8   swap#2

รอบ 2:
(3,5) ไม่สลับ → 3 5 1 8
(5,1) สลับ → 3 1 5 8   swap#3

รอบ 3:
(3,1) สลับ → 1 3 5 8   swap#4

ตอบ: เรียงเสร็จ ใช้การสลับ 4 ครั้ง
โจทย์ practice สั่ง "นับจำนวนครั้งในการสลับค่าด้วย" — ทำเครื่องหมาย ✓ ทุกครั้งที่สลับระหว่าง trace แล้วรวมตอนจบ อย่านับย้อนหลังเพราะจะตกหล่น
ติวบทที่ 3 · Insertion

Insertion Sort — หยิบมาแทรกในส่วนที่เรียงแล้ว

หลักการ
รอบ i (เริ่มที่ 1): หยิบ A[i] เป็น key
  เทียบกับตัวซ้ายทีละตัว
  ตัวไหนใหญ่กว่า key → เลื่อนขวา
  เจอตัวเล็กกว่าหรือสุดขอบ → วาง key

ซ้ายมือของ i = "ส่วนที่เรียงแล้ว"
โตขึ้นทีละ 1 ทุกครั้งที่หยิบ

/* เหมือนเรียงไพ่ในมือ:
   หยิบใบใหม่ → ไล่หาช่อง → เสียบ */
Best / Worst (ออกสอบชัวร์)
Best: ข้อมูลเรียงอยู่แล้ว {1,2,3,4,5}
  ทุก key เทียบครั้งเดียว ไม่เลื่อน
  → O(n) ← ตัวเดียวในสามตัว
    ที่ best ดีขนาดนี้แบบไม่ต้องมี flag

Worst: เรียงกลับด้าน {98,87,76,65,54}
  ทุก key เลื่อนสุดทาง
  → O(n²)

← โจทย์ practice จงใจให้ชุด
  กลับด้าน = worst case พอดี!
สังเกตโจทย์: practice ให้ 98 87 76 65 54 (มากไปน้อย) แต่สั่งเรียง "น้อยไปมาก" — นี่คือ worst case ทุก key ต้องเลื่อนไปหน้าสุดเสมอ ตารางจะยาวเต็ม อย่าตกใจว่าทำผิด
ติวบทที่ 3 · เฉลยใบ practice ข้อ 3

เฉลยจริง: Insertion 98 87 76 65 54

รอบผลลัพธ์หลังแทรกอธิบาย
เริ่ม98 87 76 65 54ส่วนเรียงแล้ว = {98}
1 (key=87)87 98 | 76 65 5487<98 → เลื่อน 98, วาง 87 หน้าสุด
2 (key=76)76 87 98 | 65 54เลื่อน 98, 87 → วาง 76 หน้าสุด
3 (key=65)65 76 87 98 | 54เลื่อน 98, 87, 76 → วางหน้าสุด
4 (key=54)54 65 76 87 98เลื่อนทั้ง 4 ตัว → วางหน้าสุด ✓
 
/* ใบ practice ให้เขียน "ทีละการเลื่อน"
   รอบ 4 จึงมีหลายแถว:
   98 87 76 65 | 54  หยิบ 54
   .. 65 _ 98        เลื่อน 98
   .. _ 87 98        เลื่อน 87  (ไล่ทีละตัว)
   54 65 76 87 98    วางลง */
/* นับการเปรียบเทียบ (worst):
   รอบ 1: 1 ครั้ง
   รอบ 2: 2 ครั้ง
   รอบ 3: 3, รอบ 4: 4
   รวม = 1+2+3+4 = 10 = n(n-1)/2 ✓
   สูตรเดียวกับ Selection! */
ติวบทที่ 3 · ตารางบังคับจำ

ตารางเทียบ 3 ตัว — ท่องเข้าห้องสอบ

SelectionInsertionBubble (มี flag)
วิธีคิดหา min มาวางหน้าหยิบไปแทรกส่วนที่เรียงเทียบคู่ติดกัน สลับ
BestO(n²) เสมอ!O(n) เรียงแล้วO(n) เรียงแล้ว
WorstO(n²)O(n²) กลับด้านO(n²) กลับด้าน
จำนวน swapน้อยสุด ≤ n−1ใช้เลื่อน (shift)เยอะสุด O(n²)
เปรียบเทียบ (worst)n(n−1)/2n(n−1)/2n(n−1)/2
3 ประโยคที่ใช้ตอบปรนัยได้ครึ่งบท:
① Selection: Best = Worst = O(n²) เพราะต้องหา min ครบทุกรอบ ไม่มีทางลัด แต่ swap น้อยสุด
② Insertion: Best O(n) เมื่อข้อมูลเรียงแล้ว — เหมาะกับข้อมูล "เกือบเรียง"
③ ทั้งสามตัวเปรียบเทียบ worst เท่ากัน n(n−1)/2 → O(n²) ทั้งคู่
ติวบทที่ 3 · เทคนิคห้องสอบ

วิธีเขียนตาราง trace ไม่ให้หลง (สำคัญมาก)

ขั้นตอนที่แนะนำ
① อ่านโจทย์: sort ตัวไหน? ทิศไหน
   (น้อย→มาก หรือ มาก→น้อย)?
   ต้องนับ swap ไหม?

② เขียนแถว "เริ่มต้น" ก่อนเสมอ

③ ทำทีละรอบช้าๆ:
   - Selection: เขียน min=idx กำกับ
   - Bubble: 1 แถวต่อ 1 การเทียบ
   - Insertion: ขีด | คั่นส่วนที่เรียง

④ จบทุกรอบ เช็คว่า
   ส่วนที่เรียงแล้ว "เรียงจริง"

⑤ แถวสุดท้ายต้องเรียงสมบูรณ์
   — ถ้าไม่เรียง แปลว่าพลาดสักรอบ
   ย้อนหาจากรอบท้ายขึ้นไป
ข้อผิดพลาดยอดฮิต (เลี่ยงให้หมด)
❌ Selection: สลับทันทีที่เจอตัวน้อยกว่า
   → ต้องหา min "จบรอบก่อน" แล้วค่อยสลับ
   (สลับกลางทางคือ Bubble ไม่ใช่ Selection!)

❌ Bubble: ลืมว่ารอบถัดไปเทียบสั้นลง
   (ท้ายสุดเรียงแล้ว)

❌ Insertion: เอา key ไป "สลับ"
   → ที่ถูกคือ "เลื่อนแล้วแทรก"

❌ อ่านทิศผิด: โจทย์ให้เรียงน้อย→มาก
   แต่มือลั่นเรียงมาก→น้อย
   → ผิดยกข้อ ทั้งที่ trace เป็น

❌ เขียนเลขตกหล่นจากแถวก่อน
   → ลอกเลขทุกตัวลงแถวใหม่ก่อนแก้

Selection Sort กับ {7, 3, 9, 1} — หลังรอบ i=0 ได้อะไร?

A {3, 7, 9, 1}
B {1, 3, 9, 7}
C {1, 3, 7, 9}
D {7, 3, 1, 9}
i=0: min=0(7) → j=1: 3<7 min=1 → j=2: 9 ไม่ → j=3: 1<3 min=3
     จบรอบ: swap(A[0], A[3]) → {1, 3, 9, 7}
