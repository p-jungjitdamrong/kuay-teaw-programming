เรื่องเล่าเปิดบทของอาจารย์: หาหนังสือ 1 ล้านเล่ม

วิวัฒนาการการค้นหา (ต้องเรียงได้)
ค้นหาหนังสือด้วย ISBN, 1 เล่ม = 6 ms

① Sequential search (ไม่เรียง)
   O(n) → 10⁶ × 6ms = 6000 วิ
        ≈ 100 นาที 💀

② Binary search (เรียงแล้ว)
   O(log n) → log₂10⁶ × 6ms
        ≈ 119.58 ms ✓

③ Hashing search
   O(1) → คงที่ ไม่ขึ้นกับ n!! 🚀

/* แปลง key → index ของ array
   ด้วยแฮชฟังก์ชัน h(k)

   key ──▶ h(k) ──▶ ช่องin ตาราง

/* ข้อจำกัดที่ออกปรนัย:

ปรนัยที่ชอบออก: "การค้นหาแบบใดเร็วสุด/ใช้กับข้อมูลไม่เรียง" — Sequential O(n) ไม่ต้องเรียง · Binary O(log n) ต้องเรียงก่อน · Hash O(1) ไม่ต้องเรียง แต่ต้องมีตาราง+ฟังก์ชัน
ติวบทที่ 5 · พื้นฐาน

h(k) = k mod m และการชน (Collision)

คำนวณ h(k) ให้คล่อง
h(k) = k mod m   (m = ขนาดตาราง)

m = 10:  h(89) = 9   h(18) = 8
         h(49) = 9   ← ชนกับ 89!

m = 7:   h(15) = 1   h(22) = 1 ← ชน!
         h(95) = 4   h(56) = 0
         h(63) = 0 ← ชน!  h(13) = 6
         h(27) = 6 ← ชน!

/* mod เร็วๆ: 95 = 7×13 + 4 → 4
   ท่องสูตรคูณแม่ 7 ก่อนเข้าห้องสอบ! */
การชน + 2 ค่ายวิธีแก้
Collision = สอง key ได้ช่องเดียวกัน
h(15) = h(22) = 1

วิธีแก้ 2 ค่าย (คำศัพท์ต้องแม่น):

① Open Hashing = Separate Chaining
   ต่อ Linked List ในช่องเดียวกัน
   (ใช้ความรู้บท 4!)

② Closed Hashing = หา "ช่องอื่น"
   ในตารางเดิม:
   - Linear probing:    f(i) = i
   - Quadratic probing: f(i) = i²
   - Double hashing:    f(i) = i·h₂(k)

   hᵢ(k) = ( h(k) + f(i) ) mod m
ระวังศัพท์สลับ: Open Hashing = แยกออกไปนอกตาราง (chaining) · Closed Hashing = ปิดอยู่ในตาราง (probing) — หลายคนจำกลับกันแล้วกาปรนัยผิด

ติวบทที่ 5 · การค้นหา (ข้อ 2 practice)

ค้นหา + นับจำนวนครั้ง — กติกาหยุด 3 ข้อ

กติกาการค้นหา (จากสไลด์อาจารย์)
เริ่มที่ h(k) แล้ว probe ตามวิธีเดิม
หยุดเมื่อเกิดอย่างใดอย่างหนึ่ง:

① พบค่า k          → "เจอ"
② พบช่องว่าง        → "ไม่เจอ"
③ ตรวจครบทั้งตาราง  → "ไม่เจอ"

นับจำนวนครั้ง = จำนวนช่อง
ที่เปิดดูทั้งหมด (รวมช่องสุดท้าย
ที่ทำให้หยุด)
ตัวอย่างจากตาราง Linear (สไลด์ 5)
ตาราง: 0:56 1:15 2:22 3:63 4:95 5:27 6:13

หา 95: h=4 → ช่อง 4 = 95 เจอ!
       → 1 ครั้ง
หา 27: h=6 → 13 ไม่ใช่ → 0:56 → 1:15
       → 2:22 → 3:63 → 4:95 → 5:27 เจอ!
       → 7 ครั้ง (แย่สุดพอดี)
หา 12: h=5 → 27 ไม่ใช่ → 6,0,1,2,3,4
       ตรวจครบตาราง ไม่มีช่องว่างให้หยุด
       → ไม่เจอ / 7 ครั้ง
เหตุผลที่ "เจอช่องว่าง = หยุดได้เลย": ถ้า k เคยถูกใส่ มันต้องอยู่ในเส้นทาง probe ก่อนถึงช่องว่างเสมอ — เจอช่องว่างก่อนแปลว่าไม่มีแน่นอน · แต่ตารางที่ "เต็ม" ไม่มีช่องว่าง → ต้องตรวจครบ m ครั้ง
ติวบทที่ 5 · เทคนิคห้องสอบ

ลำดับการทำข้อ Hashing ในห้องสอบ

ทำตามนี้ทุกครั้ง
① เขียน h(k) ของทุก key ก่อน
   ยกแผง: 15→1 22→1 95→4 ...
   (เห็นภาพรวมว่าตัวไหนจะชน)

② วาดตารางเปล่า 0..m−1

③ ใส่ทีละ key ตามลำดับโจทย์
   ชนเมื่อไหร่ เขียนสมการ probe
   ทุกขั้นจนกว่าจะลงช่อง

④ Double hashing: คำนวณ h₂
   ของ key นั้นก่อนเริ่ม probe

⑤ เสร็จแล้วนับ: จำนวนค่าในตาราง
   ต้องเท่าจำนวน key ที่แทรกสำเร็จ
จุดหักคะแนนยอดฮิต
❌ mod ผิด (95%7 คิดเป็น 5)
   → ผิดลามทั้งตาราง
   ทวนสูตรคูณแม่ m ก่อนเริ่ม!

❌ quadratic ใช้ +i แทน +i²
   (สลับกับ linear)

❌ double ใช้ h₂ ของ key ตัวอื่น

❌ probe แล้วลืม mod m
   (6+3 = 9 → ต้อง %7 = 2)

❌ นับครั้งค้นหา ไม่นับช่องสุดท้าย
   (ต้องนับทุกช่องที่ "เปิดดู")
สูตรสำเร็จเขียนตอบ: "k%m = a ชน → (a+f(i))%m = b ชน → ... = c ว่าง ∴ ใส่ช่อง c" — เขียนแบบนี้ทุก key ที่ชน คะแนนวิธีทำครบแน่นอน
