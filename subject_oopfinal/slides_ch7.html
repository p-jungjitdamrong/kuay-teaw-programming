Polymorphism — นิยามตามสไลด์อาจารย์

คำนิยาม (ตอบข้อบรรยายได้เลย)
"polymorphism คือ การที่วัตถุต่างกัน
 ตอบสนองกับข่าวสารเดียวกัน
 ในแบบที่ต่างกัน"

poly  = หลาย
morph = รูปแบบ
∴ polymorphism = หลายรูปแบบ

/* ตัวอย่างในสไลด์:
   วัตถุ "รถ" "เรือ" "เครื่องบิน"
   มี method moveTo() เหมือนกัน
   แต่ตอบสนองต่างกัน
   (วิ่ง / แล่น / บิน) */

← หลักการเชิงวัตถุ 1 ใน 3 ประการ
มาได้ 2 รูปแบบ (สไลด์บอกชัด)
① Overloading
   method ชื่อเดียวกัน "ในคลาสเดียวกัน"
   แต่ parameters ต่างกัน

② Overriding
   method ชื่อเดียวกัน
   "message signature เหมือนกันทุกประการ"
   ระหว่างคลาสแม่และคลาสลูก

/* JVM ตัดสินว่าเรียกตัวไหน:
   Overloading → ดูที่ "ลิสต์ของ parameter"
   Overriding  → ตรวจสอบตอน run-time
     วัตถุเป็นคลาสใด เรียก method คลาสนั้น
     ถ้าคลาสลูกไม่ได้ประกาศ → ใช้ของแม่ */
ข้อดีที่สไลด์ระบุ: "ทำให้เขียนโปรแกรมได้ง่ายขึ้น พัฒนาและต่อยอดได้อย่างรวดเร็ว" — เพราะโค้ดที่เรียกใช้ไม่ต้องรู้จักคลาสลูกทุกตัว เพิ่มคลาสใหม่ได้โดยไม่แก้ของเดิม

Overloading vs Overriding — ข้อสอบถามแยกทุกปี

OverloadingOverriding
อยู่ที่ไหนคลาสเดียวกันคลาสแม่ ↔ คลาสลูก
ชื่อ methodเหมือนกันเหมือนกัน
Parameterต้องต่างกัน (จำนวน/ชนิด/ลำดับ)ต้องเหมือนเป๊ะ
Return typeต่างได้ (ไม่ใช่ตัวแยก)ต้องเหมือน
ตัดสินเมื่อไหร่Compile time (ดู parameter list)Run time (ดูชนิดวัตถุจริง)
ต้องมี inheritance ไหมไม่ต้องต้องมี (extends/implements)
ชื่อเรียกอีกอย่างStatic / Compile-time polymorphismDynamic / Runtime polymorphism
ท่องประโยคเดียวจบ: Overload = ชื่อซ้ำ พารามิเตอร์ต่าง ในคลาสเดียว · Override = ลูกเขียนทับของแม่ หัวเหมือนเป๊ะ — คำว่า "signature เหมือนกันทุกประการ" ในสไลด์คือคีย์เวิร์ดของ Override

เฉลย: คลาส Dispatch — ข้อ "โปรแกรมนี้พิมพ์อะไร"

โค้ดจากสไลด์อาจารย์
public class A {
  public void callme() {
    System.out.println("A's callme");
  }
}
public class B extends A {
  public void callme() {
    System.out.println("B's callme");
  }
}
public class C extends A {
  public void callme() {
    System.out.println("C's callme");
  }
}
main + เฉลย
A a = new A();
B b = new B();
C c = new C();
A r;                // ตัวแปรชนิดแม่ตัวเดียว

r = a;  r.callme();   // A's callme
r = b;  r.callme();   // B's callme
r = c;  r.callme();   // C's callme

/* r ประกาศเป็น A ตลอด
   แต่ผลลัพธ์เปลี่ยนตาม
   "วัตถุจริง" ที่ r ชี้อยู่

   ← นี่คือ Dynamic Binding
   ตัดสินตอน run-time ไม่ใช่
   ตอน compile */
กฎทองสำหรับข้อ "พิมพ์อะไร": ดูที่ ฝั่งขวาของ new (วัตถุจริง) ไม่ใช่ชนิดตัวแปรฝั่งซ้าย · ชนิดตัวแปรมีผลแค่ตอน compile ว่า "เรียก method นี้ได้ไหม" เท่านั้น

เฉลย: OverloadTest — show() กับ show(String)

โค้ดจากสไลด์
public class A {
  private int i, j;
  public A(int a, int b) { i=a; j=b; }
  public void show() {
    System.out.println("i:"+i);
    System.out.println("j:"+j);
  }
}
public class B extends A {
  private int k;
  public B(int a,int b,int c) {
    super(a,b); k=c;
  }
  public void show(String msg) {   // Overload!
    System.out.println(msg + k);
  }
}
เฉลยผลลัพธ์
B subOb = new B(1, 2, 3);
subOb.show("This is k: ");
subOb.show();

/* ผลลัพธ์:
   This is k: 3     ← show(String) ของ B
   i:1              ← show() ของ A
   j:2                (ตกทอดมา ไม่ได้ถูกทับ) */

/* จุดสำคัญ:
   show(String) ของ B "ไม่ได้ทับ"
   show() ของ A — เพราะ parameter
   ต่างกัน = Overload ไม่ใช่ Override
   → B มี show() สองตัวให้เลือกใช้ */
จุดหลอกของข้อนี้: คนที่จำสับ Override/Overload จะคิดว่า show() ของ A หายไป — ที่จริงยังอยู่ครบ เพราะ parameter ต่างกันจึงเป็นคนละ method · เรียก subOb.show() ได้ปกติ
ติวบทที่ 7 · Interface

Interface — "บอกสิ่งที่คลาสจะต้องทำ แต่ไม่บอกว่าทำอย่างไร"

กฎ 5 ข้อจากสไลด์ (ออกปรนัยแน่)
① method เป็น public เสมอ
   และ "ไม่มี body"
   → ไม่เขียน modifier ก็เป็น
     public อัตโนมัติ

② attribute เป็นได้เฉพาะ
   "ค่าคงที่ + static"
   → ไม่เขียน final/static ก็เป็นให้เอง
   → ต้องกำหนดค่าเสมอ!

③ modifier ของ interface
   เป็นได้แค่ public หรือ default

④ interface "instantiate ไม่ได้"
   new InterfaceName(); ❌

⑤ คลาสที่ implement ต้องเขียน
   method "ทุกอัน" ที่ interface ประกาศ
   โดย signature เหมือนกันทุกประการ
Syntax
interface Rollable {
    int MAX = 100;    // = public static final!
    void roll();        // = public abstract
}

// interface สืบทอด interface ได้ (หลายตัว)
interface X extends A, B { ... }

// class ทำสัญญาด้วย implements
public class BallA extends Ball
                   implements Rollable {
    public void roll() { ... }  // ต้องมี!
}

/* ลำดับ: extends มาก่อน implements
   extends ได้แม่เดียว
   implements ได้หลายตัว คั่นด้วย , */
ข้อหลอกที่ชอบออก: "interface ประกาศ int x; ได้ไหม" → ไม่ได้ ต้องกำหนดค่าเสมอ (เพราะเป็น final) · "interface มี constructor ได้ไหม" → ไม่ได้ (instantiate ไม่ได้)

abstract class vs interface

abstract classinterface
คีย์เวิร์ดextendsimplements
ได้กี่ตัวแม่เดียวหลายตัว
fieldมีได้ทุกแบบ (private, ตัวแปรปกติ)ค่าคงที่ (public static final) เท่านั้น
method มี bodyมีได้ไม่มี (แบบดั้งเดิมในสไลด์)
constructorมีได้ (ลูกเรียก super)ไม่มี
new ตรงๆไม่ได้ไม่ได้
ความหมาย"เป็นอะไร" (is-a) สายเลือด"ทำอะไรได้" (can-do) ใบรับรอง
วิธีตัดสินใจในข้อออกแบบ: ถ้าคลาสลูกๆ "เป็นของตระกูลเดียวกัน + แชร์โค้ดกันได้" → abstract class · ถ้าแค่ "ต้องทำอะไรได้เหมือนกัน แต่คนละตระกูล" → interface (เช่น Withdrawable ที่ทั้งบัญชีและบัตรทำได้)

เฉลย lab 7: Ball + Rollable — ท่าแก้ย่อ

public abstract class Ball {
    public abstract void inflate(double volume);   // สัญญา: ต้องสูบลมได้
}
public interface Rollable { void roll(); }        // สัญญา: ต้องกลิ้งได้

public class BallA extends Ball implements Rollable {  // เป็น Ball + กลิ้งได้
    public void inflate(double v) { System.out.println("BallA inflate "+v); }
    public void roll()  { System.out.println("BallA is rolling"); }
}
public class BallB extends BallA {                     // Override เฉพาะ roll
    public void roll() { System.out.println("BallB is rolling"); }
}
public class BallC extends BallA {                     // Override เฉพาะ inflate
    public void inflate(double v) { System.out.println("BallC inflate "+v); }
}

public static void TestBall(Ball b) {          // รับชนิดแม่ → รับลูกได้ทุกตัว
    b.inflate(100);                            // Dynamic binding เลือกเอง
    if (b instanceof Rollable) ((Rollable) b).roll();  // เช็คก่อน cast
}
/* TestBall(new BallB()) → "BallA inflate 100" (ตกทอด) + "BallB is rolling" (Override)
   TestBall(new BallC()) → "BallC inflate 100" (Override) + "BallA is rolling" (ตกทอด) */

instanceof + Upcasting/Downcasting

สองทิศของการแปลงชนิด
// Upcasting — ลูก → แม่ (ทำได้เลย)
Ball b = new BallA();      // ✓ อัตโนมัติ

// Downcasting — แม่ → ลูก (ต้องเขียน cast)
BallA a = (BallA) b;         // ต้องระบุเอง

/* ทำไม upcast ปลอดภัย?
   BallA "เป็น" Ball แน่นอน (is-a)
   แต่ Ball ไม่จำเป็นต้องเป็น BallA
   → downcast ผิดตัว = ClassCastException
     ตอน run-time! */
instanceof กันพัง
if (b instanceof Rollable) {
    ((Rollable) b).roll();   // ปลอดภัย
}

/* instanceof คืน true ถ้าเป็น
   "ชนิดนั้น หรือลูกของชนิดนั้น"
   หรือ implement interface นั้น

   BallB b2 = new BallB();
   b2 instanceof BallB    → true
   b2 instanceof BallA    → true (แม่)
   b2 instanceof Ball     → true (ปู่)
   b2 instanceof Rollable → true (ผ่าน BallA) */
ข้อควรระวังเชิงออกแบบ: ถ้าโค้ดเต็มไปด้วย instanceof + cast แสดงว่า design ยังไม่ polymorphic พอ — ควรย้าย logic ไปเป็น method ใน class ลูกแทน แล้วเรียกผ่านชนิดแม่ตรงๆ

โค้ดนี้พิมพ์อะไร?

class P { void go(){ System.out.print("P"); } }
class Q extends P { void go(){ System.out.print("Q"); } }
class R extends Q { }

P x = new R();  x.go();

ใบ้: R ไม่ได้ Override go() → ไล่ขึ้นไปหาแม่
แม่ตรงของ R คือ Q ซึ่ง Override ไว้ → พิมพ์ "Q"

กฎ: ไล่จาก "คลาสของวัตถุจริง" ขึ้นไปหาตัวแรกที่มี method นั้น
ติวบทที่ 7 · ลองข้อสอบ

ข้อใดคือ Overloading (ไม่ใช่ Overriding)?

Overload = "คลาสเดียวกัน ชื่อซ้ำ parameter ต่าง" ตัดสินตอน compile จาก parameter list
Override = "แม่-ลูก signature เหมือนเป๊ะ" ตัดสินตอน run-time จากชนิดวัตถุจริง
