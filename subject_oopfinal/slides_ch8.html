เหตุผล 3 ข้อจากสไลด์ — ข้อบรรยายชอบถาม

① Logical grouping of classes
   "หากคลาสหนึ่งถูกเรียกใช้ในเพียง
    คลาสเดียว ควรให้ฝังอยู่ในอีกคลาส
    เพื่อให้ทั้งสองอยู่ด้วยกัน"
   → คลาสที่ถูกเรียกใช้ = helper class

② Increase encapsulation
   "คลาสภายในเข้าถึงข้อมูลของคลาส
    ภายนอกได้โดยตรง แม้ประกาศ private
    และคลาสภายในถูกซ่อนจากคลาสอื่นได้
    (ประกาศเป็น private)"

③ More readable/maintainable code
   "โค้ดของคลาสภายในอยู่ใกล้กับ
    ที่ที่เรียกใช้มัน"
Syntax พื้นฐาน
class OuterClass {
    // ...
    class InnerClass {
        // ...
    }
}

/* 2 ประเภทตามสไลด์:
   ① static  → "static nested class"
   ② non-static → "inner class"

   ต่างกันแค่คำว่า static ข้างหน้า
   แต่พฤติกรรมต่างกันมาก! */
คีย์เวิร์ดที่กรรมการหา: logical grouping (helper class) · เพิ่ม encapsulation (เข้าถึง private ของ outer ได้) · โค้ดอ่านง่าย/ดูแลง่าย — ตอบครบ 3 ข้อได้คะแนนเต็ม

ติวบทที่ 8 · จุดหลอก syntax

วิธี new — ท่อง 2 บรรทัดนี้ให้ขึ้นใจ

static nested — ตรงไปตรงมา
public class OuterClass {
    public static class InnerClass {
        // ...
    }
}

// สร้างจากที่ไหนก็ได้:
OuterClass.InnerClass in =
    new OuterClass.InnerClass();

/* อ่านว่า "InnerClass ที่อยู่ใน
   OuterClass" — เหมือน package */
inner class — ต้องมี outer ก่อน!
public class OuterClass {
    public class InnerClass {
        // ...
    }
}

// ① สร้าง outer ก่อน
OuterClass outer = new OuterClass();
// ② แล้วใช้ outer สร้าง inner
OuterClass.InnerClass in =
    outer.new InnerClass();
//  ↑ syntax แปลกที่คนจำไม่ได้!

/* new OuterClass.InnerClass() ❌
   ใช้ไม่ได้กับ inner class ธรรมดา */
ข้อสอบ syntax เก็งได้เลย: ให้โค้ด nested class มาแล้วถาม "บรรทัดใดสร้าง object ได้ถูกต้อง" — ดูว่ามี static ไหม: มี → new Outer.Inner() · ไม่มี → outerObj.new Inner()
ติวบทที่ 8 · ตัวอย่างในสไลด์

ตัวอย่างคลาสสิก: ArrayAlg.Pair — คืนค่า 2 ตัวจาก method เดียว

public class ArrayAlg {
    public static class Pair {              // static nested — เป็น helper ล้วนๆ
        private double min, max;
        public Pair(double f, double s) { min = f; max = s; }
        public double getMin() { return min; }
        public double getMax() { return max; }
    }

    public static Pair minmax(double[] values) {   // คืน "คู่" ค่าในครั้งเดียว
        double min = Double.MAX_VALUE;
        double max = Double.MIN_VALUE;
        for (double v : values) {
            if (min > v) min = v;
            if (max < v) max = v;
        }
        return new Pair(min, max);
    }
}

// ใช้งาน:
ArrayAlg.Pair p = ArrayAlg.minmax(d);
System.out.println(p.getMin() + " " + p.getMax());
ทำไมตัวอย่างนี้ถึงคลาสสิก: Java คืนค่าจาก method ได้ทีละ 1 ตัว — อยากคืน min กับ max พร้อมกันจึงห่อใน Pair · และ Pair ถูกใช้แค่ใน ArrayAlg จึงควรฝังไว้ข้างใน (เหตุผลข้อ ① logical grouping เป๊ะๆ)

เฉลย: ทำ DebitCard เป็น inner class ของ SavingAccount

public class SavingAccount extends BaseAccount {
    private double balance;
    private Card card;

    public SavingAccount(FixedSalary owner) {
        this.balance = 0;
        this.card = new DebitCard("xxx-xxx-5555");  // อยู่ในคลาสอยู่แล้ว → new ตรงๆ ได้
    }

    // ── inner class (ไม่ใส่ static!) ──
    public class DebitCard extends Card {
        private String cardNumber;
        public DebitCard(String cardNumber) { this.cardNumber = cardNumber; }

        public String type()     { return "visa"; }
        public double discount() { return 2.5; }

        public boolean withdraw(double amount) {
            if (amount > balance) return false;   // ← เข้าถึง balance ของ outer
            balance -= amount;                    //   ได้ตรงๆ แม้เป็น private!
            return true;
        }
    }
    public Card getCard() { return card; }
}
จุดที่ทำให้เฉลยนี้ "ดีขึ้นกว่าเดิม": เวอร์ชัน lab 7 ที่ DebitCard เป็นคลาสแยก ต้องเก็บ reference กลับไปหา account แล้วเรียก account.withdraw() — พอเป็น inner class เข้าถึง balance ได้ตรงๆ (เหตุผลข้อ ② increase encapsulation ที่สไลด์บอก)

เฉลย: NameRepository + Iterator (inner class ใช้จริง)

main ที่โจทย์กำหนด
NameRepository namesRepository =
    new NameRepository();

for (Iterator iter =
     namesRepository.getIterator();
     iter.hasNext();) {
    String name = (String) iter.next();
    System.out.println("Name : " + name);
}
// interface ที่ต้องประกาศ
interface Container {
    Iterator getIterator();
}
interface Iterator {
    boolean hasNext();
    Object next();
}
คลาส + inner class
public class NameRepository implements Container {
    private String[] names =
        {"Robert", "John", "Julie", "Lora"};

    public Iterator getIterator() {
        return new NameIterator();   // inner!
    }

    private class NameIterator implements Iterator {
        int index = 0;

        public boolean hasNext() {
            return index < names.length;  // ใช้ names
        }                                    // ของ outer ตรงๆ
        public Object next() {
            if (hasNext()) return names[index++];
            return null;
        }
    }
}
/* Output: Name : Robert / John / Julie / Lora */
ทำไม NameIterator ต้องเป็น inner (ไม่ใช่ static): มันต้องอ่าน array names ของ instance นั้นๆ — ถ้าเป็น static nested จะเข้าถึง field ปกติของ outer ไม่ได้เลย · และประกาศเป็น private เพื่อซ่อนจากคลาสอื่น (เหตุผลข้อ ②)

public class Outer {
    private int x = 10;
    public static class Helper {
        void show() { System.out.println(x); }
    }
}

ใบ้: Helper เป็น static nested → เข้าถึงได้เฉพาะ static ของ outer
แต่ x เป็น field ปกติ (ไม่ static) → compile error!

แก้ได้ 2 ทาง: ① เอา static ออกจาก Helper (เป็น inner class)
② ทำ x ให้เป็น static

Outer มี inner class ธรรมดา (ไม่ static) — สร้างยังไงถูก?

มี static → new Outer.Inner()        (ไม่ผูกกับ instance)
ไม่มี static → outerObj.new Inner()   (ต้องมี outer object ก่อน)
