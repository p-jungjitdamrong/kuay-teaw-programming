Exception vs Error — ทั้งคู่สืบจาก Throwable

นิยามตามสไลด์
"Exception คือการที่โปรแกรมพยายาม
 ทำงานบางอย่าง แต่เกิดข้อผิดพลาดขึ้น
 แล้วโปรแกรมไม่สามารถจัดการได้
 → ทำให้โปรแกรมหยุดทำงาน

 เกิดขึ้นในขณะที่โปรแกรมทำงาน (run-time)
 เช่น จะเปิดไฟล์ แต่ไฟล์ไม่มีอยู่"

/* ทั้ง Error และ Exception
   สืบทอดมาจาก java.lang.Throwable
   → มี getMessage() ใช้ได้ทั้งคู่ */

  เช่น IOException

ติวบทที่ 9 · Syntax

try-catch-finally — โครงจากสไลด์

โครงสร้าง
try {
    <statements>;          // โค้ดที่อาจพัง
}
catch (Throwable t) {      // [ ]+ = มีได้หลายบล็อก
    <statements>;          // จัดการเมื่อพัง
}
finally {                 // [ ] = มีหรือไม่ก็ได้
    <statements>;          // ทำเสมอ!
}

/* ศัพท์: try block / catch block
   / finally block */
finally สำคัญยังไง
/* finally ทำงาน "เสมอ"
   ไม่ว่าจะ:
   - ไม่เกิด exception
   - เกิดแล้วถูก catch
   - เกิดแล้วไม่มีใคร catch
   - มี return ใน try!

   → ใช้สำหรับ "เก็บกวาด"
     ปิดไฟล์ ปิด connection */

try { ... return 1; }
finally { System.out.println("bye"); }
// พิมพ์ bye ก่อน return จริงๆ!
กฎลำดับ catch ที่ออกสอบ: ถ้ามีหลาย catch ต้องเรียง ลูกก่อน แม่ทีหลัง — เขียน catch(Exception e) ไว้บนสุดแล้วตามด้วย catch ตัวเฉพาะ = compile error ("exception has already been caught") เพราะตัวแม่ดักไปหมดแล้ว
ติวบทที่ 9 · เฉลย lab 9

เฉลยจริง: num[5] เกิดอะไรขึ้น?

โจทย์จาก lab
public static void main(String[] args) {
    int num[] = {1, 2, 3, 4};
    System.out.println(num[5]);
    for (int i : num) {
        System.out.println(i);
    }
}
คำตอบ "อธิบายสิ่งที่เกิดขึ้น"
/* array มี 4 ช่อง index 0–3
   แต่เรียก num[5] → เกินขอบเขต

   → เกิด
   ArrayIndexOutOfBoundsException
   (เป็น Unchecked / RuntimeException
    → compile ผ่าน! แต่พังตอนรัน)

   ผลลัพธ์: โปรแกรมหยุดทันที
   → for loop ข้างล่าง "ไม่ได้ทำงานเลย"
   ← จุดที่ข้อสอบอยากได้ */
แก้ด้วย try-catch
public static void main(String[] args) {
    int num[] = {1, 2, 3, 4};

    try {
        System.out.println(num[5]);
    } catch (ArrayIndexOutOfBoundsException e) {
        System.out.println("Index เกินขอบเขต: "
                           + e.getMessage());
    }

    for (int i : num) {      // คราวนี้ได้ทำงาน!
        System.out.println(i);
    }
}
/* Output:
   Index เกินขอบเขต: Index 5 out of
     bounds for length 4
   1
   2
   3
   4                    ← โปรแกรมรอดแล้ว */
บทเรียนของข้อนี้: จุดประสงค์ของ exception handling คือ "โปรแกรมกู้คืนจากข้อผิดพลาดแล้วทำงานต่อได้" ตามที่สไลด์บอก — เทียบผลก่อน/หลังใส่ try-catch ให้เห็นว่า for loop ได้ทำงานหรือไม่
ติวบทที่ 9 · throw vs throws

throw กับ throws — ต่างกันแค่ตัว s แต่คนละเรื่อง

throw — "โยนออกมาเดี๋ยวนี้"
public void withdraw(double amount) {
    if (amount > balance) {
        throw new IllegalArgumentException(
            "เงินไม่พอ");
    }
    balance -= amount;
}

/* throw = คำสั่ง (statement)
   สร้าง exception object แล้วโยน
   อยู่ "ในตัว method"
   ตามด้วย object 1 ตัว */
throws — "ประกาศเตือนไว้ก่อน"
public void readFile(String path)
        throws IOException {     // ที่หัว method
    FileReader fr = new FileReader(path);
    // ไม่ต้อง try-catch ที่นี่
    // โยนต่อให้คนเรียกจัดการ
}

/* throws = ส่วนหนึ่งของ signature
   บอกว่า "method นี้อาจโยน ... นะ"
   ตามด้วยชื่อคลาสได้หลายตัว (คั่น ,)

   คนเรียก readFile() ต้อง try-catch
   หรือ throws ต่อไปอีก */
สองทางเลือกเมื่อเจอ checked exception: ① จัดการเอง ด้วย try-catch ② โยนต่อ ด้วย throws ที่หัว method — เลือกอย่างใดอย่างหนึ่ง ไม่งั้น compile ไม่ผ่าน
ติวบทที่ 9 · Custom Exception

สร้าง Exception เอง — แค่ extends

สร้างคลาส
// Checked (extends Exception)
public class InsufficientFundException
        extends Exception {
    public InsufficientFundException(String msg) {
        super(msg);      // ส่งข้อความให้ Throwable
    }
}

// Unchecked (extends RuntimeException)
public class InvalidAgeException
        extends RuntimeException {
    public InvalidAgeException(String msg) {
        super(msg);
    }
}
ใช้งาน
public void withdraw(double amt)
        throws InsufficientFundException {
    if (amt > balance)
        throw new InsufficientFundException(
            "ยอดคงเหลือไม่พอ");
    balance -= amt;
}

// ฝั่งเรียกใช้
try {
    acc.withdraw(5000);
} catch (InsufficientFundException e) {
    System.out.println(e.getMessage());
    // → ยอดคงเหลือไม่พอ
}
เลือก extends อะไร: สืบจาก Exception → เป็น checked (บังคับคนเรียกจัดการ — เหมาะกับเงื่อนไขธุรกิจที่ต้องรับมือ) · สืบจาก RuntimeException → unchecked (เหมาะกับบั๊กที่ควรแก้โค้ด ไม่ใช่ดักจับ)
ติวบทที่ 9 · อ่านผลลัพธ์

ข้อ "โปรแกรมนี้พิมพ์อะไร" — ไล่ flow ให้เป็น

public static void main(String[] args) {
    try {
        System.out.println("A");
        int x = 10 / 0;              // ← ArithmeticException ตรงนี้!
        System.out.println("B");          // ไม่ได้ทำงาน (ข้ามทันที)
    } catch (ArithmeticException e) {
        System.out.println("C");
    } finally {
        System.out.println("D");
    }
    System.out.println("E");
}
/* ผลลัพธ์: A C D E

   ไล่ทีละขั้น:
   ① พิมพ์ A
   ② 10/0 → โยน ArithmeticException ทันที
   ③ บรรทัด B "ถูกข้าม" — โค้ดหลังจุดที่พังใน try ไม่ทำงาน
   ④ กระโดดเข้า catch ที่ตรงชนิด → พิมพ์ C
   ⑤ finally ทำเสมอ → พิมพ์ D
   ⑥ ออกจากบล็อก ทำงานต่อปกติ → พิมพ์ E */
กฎ 3 ข้อสำหรับไล่ flow: ① โค้ดใน try "หลังบรรทัดที่พัง" ไม่ทำงาน ② เข้า catch ที่ชนิดตรงกันเพียงบล็อกเดียว ③ finally ทำเสมอ · ถ้าไม่มี catch ที่ตรง → finally ยังทำ แล้วโปรแกรมค่อยตาย

โค้ดนี้ compile ผ่านไหม?

try {
    FileReader f = new FileReader("data.txt");
} catch (Exception e) {
    e.printStackTrace();
} catch (IOException e) {
    System.out.println("IO error");

ใบ้: Exception เป็นแม่ของ IOException
catch(Exception) ดักไปหมดแล้ว → catch(IOException) ไม่มีทางถูกเรียก
→ compile error! ต้องเรียง ลูกก่อน แม่ทีหลัง
ติวบทที่ 9 · ลองข้อสอบ

ข้อใดเป็น Checked Exception?

Unchecked = Error + RuntimeException (compiler ปล่อยผ่าน)
Checked   = ที่เหลือทั้งหมด (compiler บังคับ) — IOException, FileNotFoundException, ClassNotFoundException

ข้อ A, B, D ล้วนเป็นลูกของ RuntimeException ทั้งหมด → Unchecked
