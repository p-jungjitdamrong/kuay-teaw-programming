ติวบทที่ 10 · ประวัติ

AWT → Swing — เรื่องเล่าที่กลายเป็นข้อปรนัย

AWT (Java 1.0)
AWT = Abstract Window Toolkit

"เรียกใช้ native GUI Toolkit
 ของแต่ละ platform อีกที
 (Windows, Macintosh, Solaris)"

ทฤษฎี: "Write once, run anywhere"
       หน้าตาต่างกันตาม platform

ความจริง (สไลด์เขียนเอง):
• ส่วนประกอบแต่ละ platform ไม่เท่ากัน
  (linux น้อยกว่า Windows/Mac)
• การตอบสนองต่างกัน
• มี bug ต่างกันในแต่ละ platform
→ "Write once, debug everywhere" 😅
Swing (ร่วมกับ Netscape)
"บริษัทซันขอความร่วมมือจาก Netscape
 ใช้ชื่อโปรเจ็คว่า Swing"

ข้อสำคัญ (ข้อสอบชอบหลอก):
Swing ไม่ได้แทนที่ AWT
 — Swing ถูกพัฒนา "บนสถาปัตยกรรม
   ของ AWT" และยังใช้
   event handling จาก AWT อยู่

ข้อดีของ Swing:
① component หลากหลายกว่า
② ขึ้นกับ platform น้อย → bug น้อย
③ หน้าตาเหมือนกันทุก platform
   (ซึ่งเป็นข้อเสียด้วย → จึงมี
    library "look and feel" ให้เลือก)
จุดหลอกอันดับ 1 ของบทนี้: "Swing มาแทนที่ AWT ทั้งหมด" → ผิด! Swing สร้างบน AWT และยังใช้ event handling ของ AWT · สังเกตชื่อคลาส: ActionListener, ActionEvent อยู่ใน java.awt.event ไม่ใช่ javax.swing

Event Handling ทำงานยังไง — 3 ตัวละคร

flow ตามสไลด์
① ระบบปฏิบัติการ "เฝ้าดูเหตุการณ์"
   (คลิกเมาส์ กดคีย์บอร์ด)
② OS แยกประเภทและส่งไปยัง
   "โปรแกรมที่ถูกต้อง"
③ โปรแกรมที่ได้รับแจ้ง
   "จัดการกับเหตุการณ์นั้น"
ผู้ใช้คลิกปุ่ม │ ▼ Event Source (JButton ที่ถูกคลิก) │ สร้าง ActionEvent ▼ Event Object (ข้อมูลของเหตุการณ์) │ ส่งให้ ▼ Event Listener (คลาสที่ implements ActionListener) → actionPerformed()
3 ศัพท์ที่ต้องแยกออก
Event Source
  = ตัวที่ "ทำให้เกิด" เหตุการณ์
    เช่น JButton, JTextField

Event Object
  = วัตถุที่เก็บ "ข้อมูลของเหตุการณ์"
    เช่น ActionEvent
    (รู้ว่าใครถูกกด เวลาไหน)

Event Listener
  = ตัวที่ "รอฟังและจัดการ"
    คลาสที่ implements ActionListener
    ต้องเขียน actionPerformed(ActionEvent e)

/* ต้อง "ลงทะเบียน" listener กับ source ก่อน:
   button.addActionListener(listener);
   ไม่ลงทะเบียน = กดปุ่มแล้วเงียบ! */
ทำไม event ใช้ interface: ActionListener คือ interface (บท 7!) — คลาสไหนก็ได้ที่ implements แล้วเขียน actionPerformed() ก็เป็น listener ได้ · นี่คือ polymorphism ทำงานจริงในไลบรารีมาตรฐาน
ติวบทที่ 10 · ท่าบังคับ

ActionListener — 3 ขั้นที่ขาดข้อไหนก็ไม่ทำงาน

import java.awt.event.*;      // ← ActionListener/ActionEvent อยู่ที่ awt!
import javax.swing.*;

public class Demo extends JFrame implements ActionListener {  // ① implements
    private JButton btn;
    private JTextField field;

    public Demo() {
        btn = new JButton("Click");
        field = new JTextField(10);
        btn.addActionListener(this);        // ② ลงทะเบียน (this = ตัวเองเป็น listener)

        JPanel pane = new JPanel();
        pane.add(field);
        pane.add(btn);
        add(pane);
        setSize(250, 120);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setVisible(true);
    }

    public void actionPerformed(ActionEvent e) {   // ③ เขียน method (บังคับ!)
        field.setText("ถูกกดแล้ว!");
    }

    public static void main(String[] args) { new Demo(); }
}
3 ขั้นที่ข้อสอบชอบเว้นให้เติม: ① implements ActionListener ② btn.addActionListener(this) ③ public void actionPerformed(ActionEvent e) — ขาดข้อ ① หรือ ③ = compile error · ขาดข้อ ② = compile ผ่านแต่กดปุ่มไม่มีอะไรเกิดขึ้น (bug เงียบ!)
ติวบทที่ 10 · หลายปุ่ม

ปุ่มหลายตัวใช้ listener เดียว — แยกด้วยอะไร?

วิธี 1: getSource() — เทียบ object
public void actionPerformed(ActionEvent e) {
    if (e.getSource() == btnAdd) {
        // ปุ่มบวก
    } else if (e.getSource() == btnSub) {
        // ปุ่มลบ
    }
}

/* getSource() คืน Object
   → เทียบด้วย == (เทียบ reference
     ว่าเป็น "ตัวเดียวกัน" ไหม)
   ปลอดภัยกว่า ไม่พลาดเรื่องข้อความ */
วิธี 2: getActionCommand() — เทียบข้อความ
public void actionPerformed(ActionEvent e) {
    String cmd = e.getActionCommand();
    if (cmd.equals("+")) { ... }
    else if (cmd.equals("=")) { ... }
}

/* getActionCommand() คืน String
   = ข้อความบนปุ่ม (label) โดยปริยาย
   → เทียบด้วย .equals() ไม่ใช่ ==
     (String! บทเรียนจาก midterm) */

/* เหมาะกับเครื่องคิดเลข —
   ปุ่มตัวเลข 0-9 ใช้ command
   เป็นตัวเลขบนปุ่มได้เลย */
จุดหลอกที่โยงกลับ midterm: getActionCommand() คืน String → ต้องเทียบด้วย .equals() · ใช้ == อาจได้ false แม้ข้อความเหมือนกัน (คนละ object) — ข้อสอบชอบเอาจุดนี้มาผสม

เฉลยโครง Calculator — ตามที่โจทย์กำหนด

public class Calculator extends JFrame implements ActionListener {
    private JButton button_1, button_2, ..., button_0;   // component เป็น field ตามโจทย์
    private JButton btnAdd, btnSub, btnMul, btnDiv, btnEq, btnClear;
    private JTextField display;
    private double num1 = 0;          // ตัวเลขตัวแรก
    private String op = "";           // เครื่องหมายที่กดค้างไว้

    public Calculator(String title) {
        super(title);                                // ตั้งชื่อหน้าต่าง
        display = new JTextField(15);
        button_1 = new JButton("1");
        button_1.addActionListener(this);           // ลงทะเบียน "ทุกปุ่ม"
        // ... ปุ่มอื่นทำเหมือนกัน ...

        JPanel panel = new JPanel(new GridLayout(4, 4));  // ปุ่มเรียงตาราง
        panel.add(button_1); /* ... */
        add(display, BorderLayout.NORTH);            // จอบน
        add(panel, BorderLayout.CENTER);             // ปุ่มกลาง
        setSize(300, 350);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setVisible(true);
    }

    public void actionPerformed(ActionEvent e) {
        String cmd = e.getActionCommand();
        if (cmd.matches("[0-9]")) {                    // กดตัวเลข → ต่อท้ายจอ
            display.setText(display.getText() + cmd);
        } else if (cmd.equals("=")) {                  // กด = → คำนวณ
            double num2 = Double.parseDouble(display.getText());
            double result = 0;
            switch (op) {
                case "+": result = num1 + num2; break;
                case "-": result = num1 - num2; break;
                case "*": result = num1 * num2; break;
                case "/":
                    if (num2 == 0) { display.setText("Error"); return; }  // บท 9!
                    result = num1 / num2; break;
            }
            display.setText(String.valueOf(result));
        } else if (cmd.equals("C")) {                  // เคลียร์
            display.setText(""); num1 = 0; op = "";
        } else {                                       // เครื่องหมาย + − × ÷
            num1 = Double.parseDouble(display.getText());
            op = cmd;
            display.setText("");
        }
    }
}
โครงที่ให้คะแนน: ① extends JFrame + implements ActionListener ② component เป็น field (โจทย์กำหนด) ③ addActionListener ทุกปุ่ม ④ actionPerformed แยกกรณีด้วย getActionCommand ⑤ เช็คหารศูนย์ (ผูกกับบท 9)
ติวบทที่ 10 · Listener อื่นๆ

Listener ตระกูลอื่นที่ควรรู้จักชื่อ

ActionListener   → actionPerformed()
   กดปุ่ม / Enter ใน JTextField

MouseListener    → mouseClicked()
   mousePressed(), mouseReleased(),
   mouseEntered(), mouseExited()
   ← ต้องเขียนครบ 5 method!

KeyListener      → keyPressed()
   keyReleased(), keyTyped()

WindowListener   → windowClosing() ฯลฯ

ItemListener     → itemStateChanged()
   JCheckBox, JComboBox
ปัญหา "ต้องเขียนครบทุก method"
/* implements MouseListener
   → ต้องเขียนครบ 5 method
     แม้ใช้จริงแค่ 1

   ทางแก้: ใช้ Adapter class
   (abstract class ที่เขียน method
    ว่างๆ ไว้ให้หมดแล้ว) */

class MyMouse extends MouseAdapter {
    public void mouseClicked(MouseEvent e) {
        // เขียนแค่ตัวที่ใช้!
    }
}
/* แต่ extends ได้แม่เดียว —
   ถ้า class ไป extends JFrame แล้ว
   ใช้ Adapter ไม่ได้ ต้อง implements
   ← trade-off ของบท 7 กลับมา */
ทำไม ActionListener นิยมสุด: มี method เดียว (actionPerformed) — implements แล้วเขียนตัวเดียวจบ ไม่ต้องพึ่ง Adapter · ข้อสอบเขียนโค้ดจึงมักใช้ ActionListener

ติวบทที่ 10 · ลองข้อสอบ

ข้อใดถูกต้องเกี่ยวกับ Swing และ AWT?

AWT: เรียก native toolkit ของแต่ละ OS → หน้าตาต่างกัน bug ต่างกัน ("write once, debug everywhere")
Swing: วาดเอง ขึ้นกับ platform น้อย → หน้าตาเหมือนกันทุกที่ + มี look-and-feel ให้เลือก
แต่ Swing ยังยืมโครง event handling ของ AWT มาใช้ทั้งดุ้น
