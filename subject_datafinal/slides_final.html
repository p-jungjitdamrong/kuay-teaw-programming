Cheat Sheet · ห้ามพลาด

10 จุดพลาดตอน trace (ข้อ 1–5)

① peek ≠ pop
   push(peek()+2): peek ไม่เอาของออก — Top ไม่เปลี่ยนตอน peek

② eval postfix: ลำดับ operand
   pop ได้ b ก่อน a → คำนวณ a−b ไม่ใช่ b−a (พังกับ − และ / ทันที)

③ วงเล็บใน postfix
   ( และ ) "ไม่ลง output" เด็ดขาด — pop ถึง ( แล้วทิ้งทั้งคู่

④ BST valid/invalid เช็คถึงบรรพบุรุษ
   ลูกขวาของโหนดฝั่งซ้าย ต้องน้อยกว่า "รากใหญ่" ด้วย ไม่ใช่แค่แม่ตรง

⑤ ลบโหนดสองลูก
   ใช้ min ของฝั่งขวามาสวม (ไม่ใช่ลูกซ้าย/ขวาขึ้นตรงๆ) แล้วไปลบตัว min เดิม
Cheat Sheet · ห้ามพลาด

10 จุดพลาดตอน trace (ข้อ 6–10)

⑥ AVL: หมุนแล้วลืมเช็คชั้นบน (ตอน delete)
   delete ต้องไล่ BF ขึ้นถึงราก อาจหมุนหลายจุด — insert หมุนจุดเดียวจบ

⑦ AVL: จำเคสจากเครื่องหมาย BF
   + ซ้ายหนัก · − ขวาหนัก · สองชั้นต่อกัน = ชื่อเคส (−2 แล้ว +1 = RL)

⑧ Heap insert วางผิดที่
   ต้องวาง "ท้ายสุด" เท่านั้นแล้วลอยขึ้น — วางที่อื่น complete พัง

⑨ Heap จมลง swap ผิดลูก
   ต้อง swap กับ "ลูกที่ใหญ่กว่า" เสมอ (MaxHeap) ไม่ใช่ลูกซ้าย

⑩ BFS/DFS ลืม visited + ลำดับเพื่อนบ้าน
   ไม่ mark = วนไม่รู้จบ · ไล่เพื่อนบ้านตามลำดับที่โจทย์กำหนด (มักเรียงตามอักษร)
ตรวจคำตอบสารพัดประโยชน์: BST/AVL → in-order ต้องเรียง · AVL → BF ทุกโหนดผ่าน · Heap → แม่ชนะลูกทุกคู่ + ไม่มีรู · Postfix → eval แล้วต้องได้ค่าเท่า infix

โจทย์ "ควรใช้โครงสร้างใด" — ตอบตามสถานการณ์

สถานการณ์ใช้เหตุผลสั้นๆ
ย้อนกลับ / undo / เช็ควงเล็บ / แปลงนิพจน์StackLIFO — ของล่าสุดออกก่อน
ต่อแถวรอคิว / BFS / round-robinQueueFIFO — มาก่อนได้ก่อน
ค้นหา + เพิ่มลบบ่อย (ข้อมูลไม่เรียง)BSTO(log n) เฉลี่ย + in-order ได้ลำดับ
ค้นหาแบบ "การันตี" ความเร็วAVLหมุนรักษาสมดุล O(log n) เสมอ
เอาตัว "สำคัญสุด" ออกซ้ำๆHeap (PQ)max อยู่ราก O(1) ดู / O(log n) ลบ
บีบอัดข้อมูลHuffman + MinHeapถี่มากรหัสสั้น prefix-free
ความสัมพันธ์โยงใยหลายทาง / เครือข่ายGraphV+E มี cycle ได้
ลำดับชั้น (โฟลเดอร์/องค์กร)Treeแม่-ลูก ไม่มี cycle
วิธีคิด: ฟัง keyword ของโจทย์ — "ล่าสุดก่อน"=Stack · "ตามคิว"=Queue · "สำคัญสุดก่อน"=Heap · "ค้นหาเร็ว"=BST/AVL · "โยงใย"=Graph
