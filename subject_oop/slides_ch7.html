Lab 7 · แนวคิด

Polymorphism = ตัวแปรเดียว หลายร่าง

เรียก method เดียวกัน แต่พฤติกรรมต่างกันตาม "ร่างจริง" ของ object — Java เลือกให้ตอน runtime (Dynamic Binding)

เห็นแล้วใน Lab 6 แต่ยังไม่ได้ตั้งชื่อ
for (Employee emp : employees) {
    emp.earnings();
    // ตัวแปรชนิด Employee เหมือนกัน
    // แต่:
    // FixedSalary   → คืน 15000
    // HourlySalary  → คืน 20×165
    // CommissionPay → คืน 95000×0.06
    // ← คนละสูตร ตามร่างจริง!
}
Dynamic Binding ทำงานยังไง
Employee e = new HourlySalary(...);
e.earnings();

// compile time: เช็คว่า Employee
//   มี earnings() ไหม → มี ✓ ผ่าน
// runtime: ดูร่างจริงของ object
//   → เป็น HourlySalary
//   → เรียก earnings() ของ
//     HourlySalary ไม่ใช่ของแม่!

// "ประกาศชนิดไหน compile เช็คชนิดนั้น
//  รันจริง วิ่งตามร่างจริง"
ประโยชน์ตัวจริง: โค้ดฝั่งเรียกใช้ (main, Cashier) ไม่ต้องรู้จักลูกทุกตัว — เพิ่มลูกใหม่พรุ่งนี้ โค้ดเดิมไม่ต้องแก้เลย
Lab 7 · interface

interface — สัญญาล้วนๆ ไม่มีของแถม

ประกาศ + ใช้งาน
public interface Rollable {
    void roll();      // ไม่มี body
}

public interface Withdrawable {
    boolean withdraw(double amount);
}

// class รับสัญญาด้วย implements
public class BallA extends Ball
                   implements Rollable {
    public void roll() { ... }
    // ต้องเขียนทุก method ในสัญญา
}
abstract class vs interface
// abstract class:
// - มี field + method ปกติได้
// - มี constructor ได้
// - extends ได้แม่เดียว
// → "เป็นอะไร" (is-a)

// interface:
// - มีแต่สัญญา (abstract methods)
// - implements ได้หลายตัวพร้อมกัน!
// → "ทำอะไรได้" (can-do)

// ใช้คู่กันได้:
// class BallA extends Ball
//             implements Rollable
// ← เป็น Ball + กลิ้งได้
จำง่ายๆ: abstract class = สายเลือด (ได้แม่เดียว) · interface = ใบรับรองความสามารถ (สะสมได้หลายใบ)

ข้อ 1: Ball + Rollable — อ่านโครงสร้าง

┌─────────────────────┐ ┌──────────────┐ │ «abstract» Ball │ │ «interface» │ │ + inflate(volume) │ │ Rollable │ └──────────┬──────────┘ │ + roll() │ extends│ └──────┬───────┘ ┌──────────┴──────────┐ implements │ │ BallA │─ ─ ─ ─ ─ ─ ─┘ └──────────┬──────────┘ extends│ ┌─────────┴─────────┐ │ BallB BallC │ ← ลูกของ BallA ได้ roll() ไปด้วย └───────────────────┘
// โจทย์กำหนด:
// Ball    = abstract class
//           มี abstract inflate(volume)
// Rollable = interface มี roll()
// BallA extends Ball
//       implements Rollable
// BallB extends BallA
// BallC extends BallA
// จุดสังเกต:
// BallB, BallC ไม่ต้อง implements
// Rollable เอง — ได้จาก BallA แล้ว!
// (inheritance ส่งต่อ interface ด้วย)

// แต่ Override roll() / inflate()
// ทับเป็นของตัวเองได้
// → ผลลัพธ์ต่างกันตามชนิดลูก
Lab 7 · ข้อ 1 เฉลย

ข้อ 1: โค้ดเต็ม + TestBall

public abstract class Ball {
    public abstract void inflate(double volume);      // สัญญา: ลูกต้องสูบลมได้
}

public interface Rollable {
    void roll();                                       // สัญญา: กลิ้งได้
}

public class BallA extends Ball implements Rollable {
    public void inflate(double volume) {
        System.out.println("BallA inflate " + volume + " cc");
    }
    public void roll() {
        System.out.println("BallA is rolling");
    }
}

public class BallB extends BallA {
    public void roll() {                               // Override ทับ
        System.out.println("BallB is rolling");
    }
}

public class BallC extends BallA {
    public void inflate(double volume) {              // Override ทับ
        System.out.println("BallC inflate " + volume + " cc");
    }
}

// static method รับ parameter ชนิด Ball — รับลูกได้ทุกชนิด!
public static void TestBall(Ball b) {
    b.inflate(100);                                    // Dynamic Binding เลือกร่างจริง
    if (b instanceof Rollable)                         // เช็คว่ากลิ้งได้ไหมก่อนเรียก
        ((Rollable) b).roll();
}

TestBall(new BallA());   // BallA inflate / BallA is rolling
TestBall(new BallB());   // BallA inflate / BallB is rolling ← roll ของ B!
TestBall(new BallC());   // BallC inflate / BallA is rolling ← inflate ของ C!
TestBall ตัวเดียวรับได้ทั้ง 3 ชนิด — แต่ผลต่างกันตามร่างจริง นี่คือโจทย์ต้องการให้เห็น Polymorphism ชัดๆ

Lab 7 · ข้อ 2 เฉลย (1/2)

ข้อ 2: Withdrawable, BaseAccount, Card, DebitCard

public interface Withdrawable {
    boolean withdraw(double amount);
}

public abstract class BaseAccount implements Withdrawable {
    public abstract boolean deposit(double amount);
}

public abstract class Card implements Withdrawable {
    public abstract String type();
    public abstract double discount();
}

public class DebitCard extends Card {
    private String cardNumber;
    private SavingAccount account;                     // บัตรผูกกับบัญชี

    public DebitCard(String cardNumber, SavingAccount account) {
        this.cardNumber = cardNumber;
        this.account = account;
    }
    public String type()      { return "visa"; }
    public double discount()  { return 2.5; }         // ส่วนลด 2.5%
    public String getNumber() { return cardNumber; }

    public boolean withdraw(double amount) {
        return account.withdraw(amount);               // รูดบัตร = ถอนจากบัญชี
    }
}
DebitCard ไม่เก็บเงินเอง — withdraw ของบัตรส่งต่อให้บัญชี (delegation) เหมือนบัตรจริงที่ตัดเงินจากบัญชีเรา

ข้อ 2: SavingAccount + Cashier จ่ายด้วยบัตร

public class SavingAccount extends BaseAccount {
    private double balance;
    private Card card;
    private FixedSalary owner;                          // เจ้าของบัญชี (Lab 6!)

    public SavingAccount(FixedSalary owner) {
        this.owner = owner;
        this.balance = 0;
        // เปิดบัตรทันทีเมื่อเปิดบัญชี (Composition ตามโจทย์)
        this.card = new DebitCard("xxx-xxx-5555", this);
    }

    public boolean deposit(double amount) {
        if (amount <= 0) return false;
        balance += amount;
        return true;
    }
    public boolean withdraw(double amount) {
        if (amount > balance) return false;             // Lab 4 สอนไว้!
        balance -= amount;
        return true;
    }
    public Card getCard() { return card; }
}

// ── Cashier v3: จ่ายด้วยบัตร ──
public void doPayment(InventoryCart ic, Card card) {
    System.out.println("CARD TYPE:" + card.type());
    System.out.println("CARD NUMBER:xxx-xxx-5555\n");

    double total = ...;  // รวมราคาจากรถเข็น (เหมือน Lab 5-6)

    double discounted = total * (1 - card.discount() / 100);
    System.out.println("CARD DISCOUNT " + card.discount() + " %");

    card.withdraw(discounted);                          // ตัดเงินผ่านบัตร → บัญชี

}
/* Output ตามโจทย์:
   CARD TYPE:visa / CARD NUMBER:xxx-xxx-5555
   ... รายการสินค้า 700 ...

Lab 7 · เครื่องมือเสริม

instanceof + casting — เช็คร่างจริงก่อนใช้

ทำไมต้องเช็ค
Ball b = new BallA();
b.roll();   // ❌ compile error!

// ตัวแปรชนิด Ball → compiler รู้จัก
// เฉพาะ method ของ Ball
// roll() อยู่ใน Rollable ไม่ใช่ Ball

// ต้องเช็ค + cast ก่อน:
if (b instanceof Rollable) {
    ((Rollable) b).roll();  // ✓
}
กฎการใช้
// instanceof คืน true ถ้า object
// เป็นชนิดนั้น "หรือลูกของมัน"

BallB bb = new BallB();
bb instanceof BallB     // true
bb instanceof BallA     // true (แม่)
bb instanceof Ball      // true (ปู่)
bb instanceof Rollable  // true (ผ่าน BallA)

// cast ลงโดยไม่เช็คก่อน เสี่ยง
// ClassCastException ตอน runtime
// → เช็ค instanceof ก่อนเสมอ
ใช้ instanceof ให้น้อยที่สุด — ถ้าเช็คชนิดเยอะๆ แสดงว่า design ยังไม่ polymorphic พอ ควรย้าย logic ไปเป็น method ใน class ลูกแทน

Lab 7 · MCQ

โค้ดนี้พิมพ์อะไร?

Ball b = new BallB();     // BallB extends BallA (Override roll เท่านั้น)
b.inflate(100);
((Rollable) b).roll();
A BallA inflate / BallA is rolling
B BallA inflate / BallB is rolling
C BallB inflate / BallB is rolling
D ClassCastException
// Dynamic Binding ดู "ร่างจริง" (BallB) เสมอ:
//   inflate() — BallB ไม่มี → ไล่ขึ้นไปเจอของ BallA → "BallA inflate"
//   roll()    — BallB Override ไว้ → "BallB is rolling"
// ตัวแปรประกาศเป็น Ball ไม่มีผลต่อว่า "ตัวไหนถูกเรียก" มีผลแค่ compile-time check
